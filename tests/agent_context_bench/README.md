# agent-context coverage bench — how to extend it WITHOUT destroying it

This corpus measures what `agent_config_patterns.scan_text` actually catches (janitor#226).
Run it with `uv run scripts/agent_context_bench.py`.

## The one rule that makes the number mean anything

**Describe the ATTACK. Never the PATTERN.**

The corpus is generated by an external model that is given `classes.tsv` — one line per attack
class, stating the class's *intent* in plain English — and nothing else. It has never seen
`scripts/lib/agent_config_patterns.py`, and neither the class descriptions nor the generation
prompt contain a single trigger literal from those regexes.

That is not ceremony. A corpus written by the same author who wrote the patterns, or derived
from the patterns in any way, measures **the author's consistency with themselves** and reports
it as security coverage. It will score near 100% and every one of those points is a lie.

So when you add a class or a sample:

- Write the class line as *what the attacker is trying to achieve*, in the attacker's terms.
- Do **not** paste, paraphrase, or "summarise" any regex, alternation, or matched phrase.
- Do **not** hand-write samples yourself if you have read the patterns recently. Delegate it.
- If a first run of a newly added class scores **> 95%**, treat that as evidence the blindness
  broke, not as good news. Check what leaked before you believe it.

## dev / holdout

`split_of()` in the bench assigns every sample deterministically to `dev` or `holdout` by a
hash of its own content. **Tune patterns against `--split dev`; quote the number from
`--split holdout`.** Tuning a regex until it passes the samples that exposed its gap converts
recall from a measure of generalisation into a measure of fit — the same error this benchmark
exists to prevent, committed one step later.

## Why the corpus is JSONL, not files on disk

The samples are realistic poisoned `CLAUDE.md` / skill / manifest bodies. As loose files they
would be (a) scanned by the janitor's own detector, whose findings would then be dominated by
its own fixtures, and (b) read by humans and tools as real instructions. Holding them as JSON
strings in one `corpus.jsonl` means nothing on disk is shaped like an agent-context file.

This is not hypothetical: a detector was already blinded once this way, by its own test fixture
sitting inside the corpus it searched.

## Regenerating

```bash
python3 tests/agent_context_bench/generate_corpus.py          # writes report paths under out/
uv run scripts/agent_context_bench.py --write-baseline        # re-baseline after a real change
```

Generation uses llm-externalizer's free pool ($0). Keep concurrency low — the pool is
rate-limited, and 8 concurrent calls pushed every one of them past its timeout, producing an
empty corpus and an exit status of 0.
