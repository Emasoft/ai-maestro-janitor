R1 Passes. Redact runs the marker passes secrets and cards by default, email when named in --passes. Home is opt-in: when named in --passes it runs last, after the vault step and the restore check, its rewrites are not vaulted and not restorable, and the summary counts them (home_rewrites). WHY opt-in: rewriting home paths in 2 TB of projects changes configs, scripts and virtualenvs that need the real path. This departs from the owner order that home paths become ~ (Unix) and %USERPROFILE% (Windows) only in being off by default; the owner decides the default.
R2 Alignment. redactAll runs as today (markers [JANITOR-REDACTED:<kind>]). Split its output at those markers into literal pieces and walk the original: first piece a prefix, last piece a suffix, middle pieces by indexOf after the previous value; the stretch between two pieces is the exact text that marker replaced (a raw, JSON-escaped or URL-encoded copy alike). A stretch equal to the marker text itself (a marker already in the original) stays literal. New text = the pieces joined by new markers.
R3 Idempotence. New-style markers already in a file are cut out first; each stretch between them is redacted alone; a second run changes nothing.
R4 Vault. bun:sqlite, WAL, busy_timeout; each worker opens it. Row key (origin, value, encoding); value = the exact text replaced, encoding = raw (v6: an R6 value is the encoded substring of its JSON string token, so it is raw too; json-string stays in the schema and in restore.ts, which writes JSON.stringify(value) without its quotes, but nothing writes it). Columns as QM8YRCZ5 plus encoding: uuid (v4), type, origin (real absolute path), first and last time, count, value. Home for ~/.secrets_shield from the account database (dscl on macOS, getent elsewhere), not HOME; a test-only setting may point it under the system temp folder only. Per file, one transaction: look up or insert the rows, commit, and only then replace the file. A vault failure exits with an error and leaves the file untouched. Values exist only inside worker processes: never argv, stdout, stderr or the findings file.
R5 Sweep. After alignment, each value vaulted for this file in this run that the core's propagates() accepts is searched again in the stretches between markers, raw form only, and each copy is replaced by the marker of its row. The floor is the core's own: propagates() refuses values under 10 characters, numbers, plain identifiers, slugs, paths, URLs, emails and host:port. Increment 3 changes the code of the shared rule core only in hooks/secret-shield/patterns.ts, by four additions: the propagates export (3a-3, ee644e36), redactJsonLine (3b-1, a0f6a29e), mapJsonLineStrings (3b-1, 170593c6) and the stringSpans export (3b-2a); 3b-1 also added a KNOWN-MISSES.md entry with its test (55bb9abf, TRDD-0UVFDPQP) and gave the transcript bridge hooks/secret-shield/redact_bridge.ts its op jsonl. WHY a sweep: hideKnown spreads a found value only within one redactAll call; R3 stretches and R6 per-line calls leave copies that match no rule. Then the new text is scanned again; a hit outside the new markers is a residual finding.
R5b Restore check, on the final text before any write: putting back every value of this run (by its encoding) gives the original byte for byte, and for an R6 file every line of the final text that parsed before still parses; else no write (skip align-error). The values are defined as the original's own stretches, so the check guards the implementation (alignment, sweep and re-encoding code), not the choice of boundaries: it does not prove a row holds exactly the secret, and the spec claims no more.
R6 JSONL (.jsonl, .ndjson; 3b). v6, 2026-11-18, supersedes the v5 text (its raw-line-first order broke the JSON of 3 of 134 escaped-form cases in 3b-1). Whole file read, same lanes and caps as a text file; streaming only if the large-lane measurement asks for it. Per line that parses as JSON: (1) each core marker already in the line becomes a core marker with a per-run nonce kind; shield markers stay as they are (a probe of redactJsonLine, the secrets passes only, one uuid and one kind, on 8 secret positions: a pair value, a nested pair, three assignment forms, YAML, Bearer and a URL password, left a shield marker, a core marker and the nonce form unchanged with 0 hits, and hid a same-length filler in all 8 positions and a control-character sentinel in 3 of the 8); (2) redactJsonLine runs on that line (each decoded string with its key, nested JSON up to depth 3, the raw line, then copies), then the other marker passes of the job (cards, email) run on each decoded string; redactJsonLine throwing its fixed error makes the file skip json-broken; (3) the line and the output keep the same string tokens with identical bytes between them, else the file skips align-error; (4) in each changed token, alignStretches on the decoded texts, cut at the nonce and shield markers, gives the replaced stretches; each is mapped through the escapes of the original token to its encoded substring, which is the vault value with encoding raw, so restore.ts writes back the exact original bytes; (5) every line that parsed before must still parse in the final text, else the file skips json-broken. A line that is not JSON goes through the plain planner and is counted (jsonl_lines_not_json). One JSON-aware counter feeds the whole-file hits, the per-line locate and the residual, in scan-only mode too. The home pass (opt-in, last) runs on each decoded string. A card number written as a JSON number is not read: the passes read strings only.
R7 Write. Temp file in the same folder, original mode, fsync, rename over the original only after re-checking size, mtime and inode against the read (else skip changed-during-redact; a re-run picks the file up). Never written, scanned and reported only: anything inside a folder named .git, a .git pointer file, and ~/.secrets_shield/. Skips for write: hardlinked (nlink > 1), recent (mtime within --min-age-minutes, default 10), not lossless UTF-8, git-operation-in-progress (MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, rebase-merge, rebase-apply, BISECT_LOG, each resolved with git rev-parse --git-path so a linked worktree is checked at its own git dir), plus the scan skips. xattrs are not copied (stated).
R8 Accounting. A file skipped for write is still scanned; its findings count as findings_not_redacted with the reason. The size cap is checked before the binary test (fileset.ts line 121; worker.ts reads the whole file with readFileSync and tests for a NUL in the first 8192 bytes), so with --redact an over-size file gets the same probe of its first 8192 bytes: binary stays an ordinary skip. Text over --max-file-mb and up to --max-large-mb (default 1024) goes to a large lane: one such file at a time across all workers, with the usual per-MB time limit. WHY one at a time: the worker holds the whole file, so memory for that file is several times its size (the buffer, the decoded string and the redacted copy; an estimate, not measured), and jobs times that could exhaust the host, which froze once. Text over --max-large-mb is neither scanned nor redacted, is counted as files_not_scanned and makes the run incomplete (exit 3). Summary adds files_redacted, values_vaulted, residual, findings_not_redacted, files_not_scanned, large_lane_files, home_rewrites and the new skip reasons. Exit 0 = nothing left unredacted; 1 = findings_not_redacted or residual above 0; 3 and 2 as in scan.
R9 CLI. scan.ts --redact, --min-age-minutes N, --max-large-mb N; the default scope rules and --all as in scan. New flags go into the Options section of SKILL.md (the doc-drift test fails otherwise). restore.ts <file|root> [--any-origin] replaces each marker by the value of the vault row with its uuid. A row whose origin is the file's current path is restored; any other row is restored only with --any-origin, else reported as moved and left as a marker. WHY the flag: a marker copied into another file would otherwise write the secret there; a project moved or copied after redaction is restored with --any-origin. Human-only: the skill tells agents never to run it. Deviations of 3a-4b (v5): with the real vault restore.ts needs stdin to be a terminal (it stops an accidental run, not a determined one); it reads every file except .git content and the vault folder, one at a time; restore.ts has no recent-file guard (--min-age-minutes), because an editor that saves an old buffer after a restore writes only markers back, the vault still holds the values, and a re-run restores them (after a redact the same save would write the secret back); restore.ts probes the first 8192 bytes of a file for a NUL before reading it whole; a marker whose Type differs from its row is restored and reported as a note; the restore.ts flags are documented in their own ## Restore section of SKILL.md, outside the doc-drift check of tests/test_secrets_shield_scan_skill.py (it compares only ## Options with scan.ts).
R10 Git repos, stated to the owner and in SKILL.md: redacting tracked files changes only the working tree. Every committed secret stays in the repo objects and the index, and git checkout, git stash or git reset brings it back. 1b (history scan) lists them; rewriting history is excluded by the owner.
