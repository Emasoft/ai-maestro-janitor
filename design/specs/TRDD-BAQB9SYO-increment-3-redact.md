# TRDD-BAQB9SYO increment 3: redact mode (spec v2)

Owner 2026-11-17 (verbatim): "the priority is the secrets-shield-scanner. i need it now to redact 2 terabytes of projects, some with gits and jsonl full redaction." Vault: TRDD-QM8YRCZ5 (plain SQLite ~/.secrets_shield/vault.db, no encryption; marker [REDACTED-BY-SECRET-SHIELD. Type: <kind>. ID: <uuid>]; restore is human-only). Git history is never rewritten (owner): working-tree files only. Split: 3a = vault, plain-file redact, sweep, restore, tests; 3b = JSONL (R6).

Measured 2026-11-17 (one probe each): (a) redactAll with the home pass turns a home prefix into ~, which is not a marker; (b) the rule kind assignment fires on the raw JSON pair "password":"hunter2zzq" and on nothing in the bare value hunter2zzq, so key and value must be seen together; (c) short values (ab, x1, zq, abc) after password, token, key and secret names match no rule; (d) the email pass redacts an address at a real domain and keeps one at example.org; (e) one lsof sample of the live transcript of this session, taken while the session was idle, printed no holder.

R1 Passes. Redact runs the marker passes secrets and cards by default, email when named in --passes. Home is opt-in: when named in --passes it runs last, after the vault step and the restore check, its rewrites are not vaulted and not restorable, and the summary counts them (home_rewrites). WHY opt-in: rewriting home paths in 2 TB of projects changes configs, scripts and virtualenvs that need the real path. This departs from the owner order that home paths become ~ (Unix) and %USERPROFILE% (Windows) only in being off by default; the owner decides the default.
R2 Alignment. redactAll runs as today (markers [JANITOR-REDACTED:<kind>]). Split its output at those markers into literal pieces and walk the original: first piece a prefix, last piece a suffix, middle pieces by indexOf after the previous value; the stretch between two pieces is the exact text that marker replaced (a raw, JSON-escaped or URL-encoded copy alike). A stretch equal to the marker text itself (a marker already in the original) stays literal. New text = the pieces joined by new markers.
R3 Idempotence. New-style markers already in a file are cut out first; each stretch between them is redacted alone; a second run changes nothing.
R4 Vault. bun:sqlite, WAL, busy_timeout; each worker opens it. Row key (origin, value, encoding); value = the exact text replaced, encoding = raw, or json-string for an R6 step-2 value (restore then writes JSON.stringify(value) without its quotes, so a quote, backslash or newline stays escaped). Columns as QM8YRCZ5 plus encoding: uuid (v4), type, origin (real absolute path), first and last time, count, value. Home for ~/.secrets_shield from the account database (dscl on macOS, getent elsewhere), not HOME; a test-only setting may point it under the system temp folder only. Per file, one transaction: look up or insert the rows, commit, and only then replace the file. A vault failure exits with an error and leaves the file untouched. Values exist only inside worker processes: never argv, stdout, stderr or the findings file.
R5 Sweep. After alignment, each value vaulted for this file in this run that the core's propagates() accepts is searched again in the stretches between markers, raw form only, and each copy is replaced by the marker of its row. The floor is the core's own: propagates() refuses values under 10 characters, numbers, plain identifiers, slugs, paths, URLs, emails and host:port. The only core change of increment 3 is exporting propagates from hooks/secret-shield/patterns.ts. WHY a sweep: hideKnown spreads a found value only within one redactAll call; R3 stretches and R6 per-line calls leave copies that match no rule. Then the new text is scanned again; a hit outside the new markers is a residual finding.
R5b Restore check, on the final text before any write: putting back every value of this run (by its encoding) gives the original byte for byte for raw rows, and for an R6 file every line parses and equals the original line as JSON; else no write (skip align-error). The check proves the file is restorable; it does not prove each row boundary is the secret's exact boundary, and the spec claims no more.
R6 JSONL (.jsonl, .ndjson; 3b). Streamed line by line, so no --max-file-mb cap. Per line: (1) the raw-line pass of R2 (keys and values seen together, as scripts/lib/transcript_redact.py does), then a parse check: a line that parsed before and no longer parses makes the file skip json-broken; (2) each JSON string token of the result is decoded; a decoded value with a hit is redacted by R2 on the decoded text, vaulted with encoding json-string, and re-encoded with JSON.stringify; other tokens untouched (numbers never re-serialised); (3) R5 over the whole file. A line that is not JSON is redacted as text and counted (jsonl_lines_not_json).
R7 Write. Temp file in the same folder, original mode, fsync, rename over the original only after re-checking size, mtime and inode against the read (else skip changed-during-redact; a re-run picks the file up). Never written, scanned and reported only: anything inside a folder named .git, a .git pointer file, and ~/.secrets_shield/. Skips for write: hardlinked (nlink > 1), recent (mtime within --min-age-minutes, default 10), not lossless UTF-8, git-operation-in-progress (MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, rebase-merge, rebase-apply, BISECT_LOG, each resolved with git rev-parse --git-path so a linked worktree is checked at its own git dir), plus the scan skips. xattrs are not copied (stated).
R8 Accounting. A file skipped for write is still scanned; its findings count as findings_not_redacted with the reason. A plain file over --max-file-mb is neither scanned nor redacted: with --redact it makes the run incomplete (exit 3) and is counted as files_not_scanned. Summary adds files_redacted, values_vaulted, residual, findings_not_redacted, files_not_scanned, home_rewrites and the new skip reasons. Exit 0 = nothing left unredacted; 1 = findings_not_redacted or residual above 0; 3 and 2 as in scan.
R9 CLI. scan.ts --redact, --min-age-minutes N; the default scope rules and --all as in scan. New flags go into the Options section of SKILL.md (the doc-drift test fails otherwise). restore.ts <file|root> replaces markers whose row origin equals the file path by the vault value, human-only: the skill tells agents never to run it.
R10 Git repos, stated to the owner and in SKILL.md: redacting tracked files changes only the working tree. Every committed secret stays in the repo objects and the index, and git checkout, git stash or git reset brings it back. 1b (history scan) lists them; rewriting history is excluded by the owner.
R11 Tests (real git, real bun, vault under tmp): redact then restore byte-identical; same value twice in one file gives one uuid, in two files two uuids; second run changes nothing; a copy left by R3 is swept, a short value (under 10 characters) is not; gitignored .env untouched by default and redacted with --all; merge-in-progress repo and linked worktree untouched; recent, hardlink and invalid UTF-8 skipped but counted in findings_not_redacted; over-size file gives exit 3; nothing under .git rewritten; findings file and stdout never hold a value; vault write failure leaves the file unchanged; (3b) escaped PEM key and a raw "password" pair redacted, lines still parse, numbers equal, restore of a json-string value with a quote keeps the line parsing. Test data under 4 GB.

The other machine gets the code through a release (3.9.9 is gated on CPV PR 278, which the owner must merge) or by copying a checkout of this repo there and running bun run <checkout>/scripts/shield_scan/scan.ts, which needs bun and git but no plugin install.
