## C1 skills/janitor-secrets-shield-scan/SKILL.md

Shape of skills/janitor-safe-delete/SKILL.md: frontmatter name and description (when to use, trigger phrases: scan for secrets, find leaked API keys or tokens, audit a project or a folder tree for credentials, /janitor-secrets-shield-scan), then Overview, Prerequisites, Instructions, Options, Exit codes, Output, Error Handling, Examples, Scope, Resources, Checklist.
- Prerequisites: bun and git on PATH; ${CLAUDE_PLUGIN_ROOT} set. Tested on macOS only.
- Instructions: root = the path in $ARGUMENTS, else the cwd. Pass the user options through. Run: bun run "${CLAUDE_PLUGIN_ROOT}/scripts/shield_scan/scan.ts" [options] [root]. A large tree takes hours: run it with run_in_background and read the two stdout lines when it ends; never poll.
- A section headed exactly "## Options" lists the CLI options and nothing else: --all, --passes, --jobs, --out, --max-file-mb, --file-timeout-base, --file-timeout-per-mb, each with one line on what it does and its default, exactly as D3. No other --flag token appears inside that section.
- A section headed exactly "## Exit codes", as D9: 0 complete and no findings; 1 complete with findings; 3 incomplete (a timeout, read-error, crash, git-error or unreadable-dir skip), whatever the findings; 2 usage or fatal error (stderr holds a fixed text; show it).
- Output: stdout is the summary JSON line and the findings file path. Report in words: files_scanned, bytes_scanned, findings, files_with_findings, each nonzero skipped reason, complete, mb_per_s, and the findings file path. When gitignored_entries > 0, ignored_repos > 0 or ancestor_rules_skipped is true, say in plain words what was not scanned (for example "140 gitignored entries and 40 repositories inside ignored folders were not scanned") and name --all. Never call a run clean when complete is false or when any of those three is set.
- The findings file: JSON lines of type finding (path, kind, line or null, count), skip (path, reason) and the summary last; it never holds a secret value. Default ~/.secrets_shield/scans/<root name>-<timestamp>.jsonl, mode 0600; a path inside any git work tree is refused (exit 2), because the file says where the secrets are. On request list files and kinds from it (for example with jq); never open or print the flagged lines of the scanned files, since they hold the secrets. A finding with line null was found in the whole file but not on one line (a secret split over lines, or the per-line pass was killed by the time limit).
- Scope and limits, stated in the skill: default scope follows .gitignore, .git/info/exclude and the global excludes file; ignored folders and the repositories inside them are not scanned; --all scans every file including hidden and ignored ones and each repository .git/config, never other .git content; symlinks are never followed; a file over --max-file-mb is skipped; git history is not scanned yet (a later version); nothing is redacted (scan only); a repository two or more levels below an ignored folder is skipped and not counted in ignored_repos.

## C4 Read timing (dev measurement, not shipped)

Question: on this host, how fast are parallel reads of the default-scope file set compared with the full scan, so increment 2 knows whether the passes or the reads bound the speed.
- Script scripts_dev/shield_scan_read_timing.ts (gitignored): imports walkFiles and newStats from scripts/shield_scan/fileset.ts, reads each FileItem with node:fs/promises readFile at a concurrency of --jobs, decodes UTF-8 like worker.ts, and prints one JSON line: files, bytes, elapsed_s, mb_per_s, jobs. It stops reading at 2 GB (under the owner cap of 4 GB on test data; reading in place creates nothing). It differs from the scan in one way, stated in the report: reads run in one process, the scan uses child processes.
