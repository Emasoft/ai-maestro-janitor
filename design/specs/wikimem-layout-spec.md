### Locations and slugs
- WL-1. LOCAL memory lives directly in `~/.claude/projects/<slug>/memory/`, with no `wikimem/` subfolder. Source G15, G16.
- WL-2. LOCAL design lives in `~/.claude/projects/<slug>/design/` (TRDD-M5BRPISQ). Source G15. Risk: F4 does not list design/ as protected or as deleted; VERIFY-3.
- WL-3. The slug of the CURRENT session is Claude Code's: the launch path as given, non-alphanumeric to `-`. Claude Code truncates a very long path and adds a hash suffix (F1); that slug is not computed but found through the recorded cwd (WL-4) until VERIFY-10 measures the rule. Source G24 (supersedes G23). Evidence F1. New LOCAL pages and LOCAL cards are written under this slug (WL-5 for worktrees).
- WL-4. A project's slug SET is built per SESSION, not per folder-wide cwd list. Each session file is classified by its LAUNCH cwd, the first line that carries a `cwd` (F3); later lines are ignored, because a session's cwd can change mid-session. Each kind of launch-cwd evidence has one fixed effect, given in the WL-4 decision table below. Rules that apply to every row: (a) a live launch cwd (it exists on disk) is classified by git toplevel, not by path prefix: `git -C <cwd> rev-parse --show-toplevel` is compared with the project's toplevel and its worktree paths (`git worktree list`); (b) a dead launch cwd cannot be asked for its toplevel, so it is compared as a path; (c) all path matching compares whole path components, and "matches" means that the launch cwd equals the recorded path or lies under it, by whole components (a launch cwd `/x/foo/bar` lies under `/x/foo`, and `/x/foobar` does not); (d) every toplevel, root and worktree path is compared in one canonical form, the realpath of each, or for a dead path the realpath of its longest existing ancestor plus the remaining components, because `--show-toplevel` resolves symlinks and `~/Code` is a symlink to the volume path; (e) a git error on a live cwd (a safe.directory refusal, a corrupt or bare repository, git missing) makes that session unknown, it is reported, and it never falls back to path-prefix membership; (f) if the project root is not a git repository, membership uses path components, with nested `.git` entries still excluded; (g) nested repositories are found by `git submodule status` and by any `.git` entry under the root (except the project's own worktrees, see E1); (h) when one dead launch cwd matches several rows, the row whose recorded path is the longest canonical path, by whole components, wins; a nested repository path is one such recorded path, so it beats the root that contains it. The map slug to realpath is cached and refreshed when a folder's newest session file changes, and git answers are cached per distinct launch cwd as well as per folder. Apart from the alias rule (folder name equals slug(p) for a known alias path p of the current root: realpath, launch path, `$PWD`, and every top-level symlink in the home directory that point at an ancestor of the root), a folder is never added on its name alone, because slugging is lossy (`/a-b` and `/a/b` give the same slug); a long-path slug is found only through its recorded cwd (WL-3). Worktree slug folders (F16) belong to the set through their launch cwds; they are searched and ARE write targets for sessions launched in that worktree (WL-5), and they persist after a worktree is removed because they live under ~/.claude/projects, not in the checkout. Source G25 (D for the method), G24, G15. Evidence F1-F3, F16.

  WL-4 decision table. JOIN means the folder is searched (WL-5); SHARED means the folder is marked `slug-folder-shared` and the conflict is reported (F16: report line 31, `-Users-USER-Code-EMASOFT-INTEGRATOR-AGENT`). The current session always writes to its own launch slug folder (WL-3), the folder Claude Code itself writes its notes into. The column WRITE TARGET FOR OTHER SESSIONS governs only whether the resolver may choose a folder for writes when that folder is NOT the current session's own launch slug folder.

  The current session's own launch slug folder is always searched by that session and always receives its writes, even when the table blocks or shares it; the conflict is reported. This keeps a session's own pages findable (G25).

  | Launch-cwd evidence | Effect on JOIN | Effect on WRITE TARGET FOR OTHER SESSIONS | SHARED marking |
  |---|---|---|---|
  | Live cwd, toplevel equals the project's toplevel or one of its worktrees | member | member | no |
  | Live cwd, toplevel is a different repository (including a submodule, or a nested or vendored repository inside the root) | blocks join | blocks | folder is `slug-folder-shared` |
  | Live cwd in no git repository, inside a non-git root (equals or lies under the root, by whole path components) | member | member | no |
  | Live cwd in no git repository, outside the root | blocks join (evidence of another project) | blocks | no, unless another row also marks it |
  | Live cwd, git error | unknown: no effect on join | unknown: no effect | no; reported |
  | Dead cwd that equals or lies under, by whole path components, the root, an alias path, a worktree path (including `.claude/worktrees/*`), or a remembered worktree path | member | member | no |
  | Dead cwd inside a known nested repository path or a remembered former nested repository path | blocks join | blocks | folder is `slug-folder-shared` |
  | Dead cwd that equals or lies under, by whole path components, a path recorded for another project (only if such a record exists) | blocks join | blocks | folder is `slug-folder-shared` |
  | Dead cwd matching nothing | does NOT block join | blocks the write-target role only; reported | no |
  | Folder name equals slug(alias) (alias rule, as defined above) | member only if the folder has no join-blocking row and no dead cwd matching nothing | follows the other rows | follows the other rows |
  | Folder with no positive row | unknown: not searched, but listed if it holds pages (adoption below) | no | no |

  Precedence: rule (h).

  A folder joins the slug set if and only if it has at least one member row and no join-blocking row. The alias row is stricter than the session rows because a name match is lossy (WL-4 above: slugging collapses distinct paths), so a name match alone is not enough and needs clean evidence from every session in the folder. A shared folder is searched by none of the projects involved, except by a session launched in it (E2). A dead launch cwd never adds a folder on its own unless it equals or lies under a member path by whole components (F2: 38 of 119 recorded cwds are gone). Former nested repository paths are recorded only when the resolver saw them, so that exclusion is best-effort. A dead launch cwd inside a nested repository path, known or remembered, never counts as a member merely because its string lies under the root. A path record for another project exists only for projects whose resolver has run on this machine; without it the "matches another project" row cannot fire. Mixed rows inside one folder arise only from a lossy-slug collision or from a path reused over time, because every session in a folder was launched from paths with the same slug; tests should target those two cases. A live cwd in no git repository outside the root does not mark the folder shared, because nothing proves it is a project; the other project's resolver may still mark the folder shared, and that asymmetry is accepted. A git error on a foreign session can let a folder join that should have been shared; this risk is accepted and reported.

  Adoption. An unknown folder that holds memory pages is not dropped silently, because a moved or renamed project would otherwise lose its pages (G25: a page is never reported missing because of the wrong slug). The resolver lists it, and adopts it only when a page's `project-id` frontmatter names this project (WL-7; `scope` is not used). Because a `project-id` can be shared by two projects (F15), automatic adoption waits on VERIFY-4 (unique project identity) and VERIFY-12; until both close, the resolver lists and reports the folder and does not adopt it. The remembered state (adopted aliases, worktree paths seen, former nested repository paths, and any per-project path record) is stored in one file in the folder `~/.claude/projects/<slug of the realpath of the main worktree's git toplevel>/` (for a non-git root, the realpath of the root), created if missing, so that every session of the project, whatever its launch path or worktree, reads and writes the same file. Writes are append-only lines made under an exclusive file lock, so concurrent sessions lose no updates; a wrong adoption is undone by appending a line that revokes it; the slug-resolver card implements it. That folder joins the slug set through the alias rule (the realpath of the root is an alias). The state file is never indexed as a page. When the main worktree moves, the resolver records the old state location as an alias and carries its lines forward, until VERIFY-4 provides a project identity that does not move, at which point the location is keyed on that identity.

### Page identity and copies
- WL-13. Every page gets a unique id in frontmatter, `page-id: PAGE-XXXX-XXXX`, minted like atom ids. `name:` stays the human slug. Two files are copies of one page if and only if they share `page-id`. Source G19 ("they have all an unique id") + D (names collide across projects, F8).
- WL-14. Copies are allowed and recommended (G21). Inside one project (its LOCAL and PROJECT scopes and its slug set) and the shared USER root, memgrep applies a write to every copy it can see in one journalled transaction that holds every affected scope's lock; moving an atom between two pages updates every copy of both (G20). Copies in another project's repository are synced PULL-ON-ACCESS: when the importing project indexes or reads a copy, memgrep refreshes it from its owner's file; nobody writes into another repository. This deviates from G20 ("at the same time") for cross-project copies (WL-CONF-4). Source G19, G20, G21 + D (pull-on-access). Evidence F7 (today copies drift; the write gate sees only the current batch).
- WL-15. The atom-id uniqueness rule changes: one atom id may appear in several files only when those files share one `page-id`; anywhere else it stays an error. Source D. Evidence F7.
- WL-16. Copies found with different content (edited outside memgrep) are reported (`page-copies-diverged`) and writes to that page are refused until `memgrep reconcile <page-id>` resolves them by an explicit choice; memgrep never picks a winner by itself. The report and the refusal apply only to copies inside one project or the USER root: a read-only imported copy (WL-18) whose owner file is newer is neither flagged nor blocked, because memgrep refreshes it pull-on-access (WL-14). Source D (never assume which copy is right).

To change it locally an agent forks it into a new page with a new `page-id`. This reconciles G19 (read-only elsewhere) with G20/G21 (copies stay in sync). Source D; WL-CONF-2.

## WL-CONF — conflicts between owner rules and how this draft resolves them

- WL-CONF-1. G17 puts the project index in "each project design folder"; G18 says memories and their index share a folder. Resolution WL-10 (G18), because an index in design/ would sit beside TRDD cards, not beside the pages it indexes.
- WL-CONF-2. G19 makes other projects' pages read-only; G20/G21 keep copies in sync and recommend copying. Resolution WL-18: importing projects pull the owner's file on access (WL-14); they read but do not edit.
- WL-CONF-3. G15 puts LOCAL memory in "the same folder of claude code memories"; G24 follows Claude Code's slug, which splits a project across launch paths (F2). Resolution WL-4/WL-5: search the whole slug set, write to the current slug.
- WL-CONF-4. G20 says copies update "at the same time. instant synch". Across two repositories that cannot be done without writing into a repository the session does not own, and the write gate does not cover other pages (F7).
