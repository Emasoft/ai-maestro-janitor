# TRDD-d151fe52 — memgrep

## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative) — 2026-06-06

**What:** `memgrep` — a cross-platform, markdown-syntax-AWARE grep written from scratch in
Rust, plus agent-memory helpers. It is the query engine for the markdown memory system
(see the wiki/KB design — pure-markdown, git-tracked, one-fact-per-line, auto-`memory-index.md`).
It exists because plain `rg` is markdown-blind: it cannot exclude code blocks, scope to a
heading/chapter, range over heading numbering, match only bold/span-tagged text, or follow
the link/TOC graph — and ~90% of the requested features are AST-level, not line-regex.

**Architecture decision (made 2026-06-06):** FROM-SCRATCH Rust, NOT an `rg`-binary wrapper —
but built ON ripgrep's *library crates* so we inherit its speed + traversal:
- `ignore` — ripgrep's gitignore-aware parallel directory walker.
- `regex` — ripgrep's exact matching engine (RE2-style, linear-time).
- `comrak` — GFM CommonMark AST with `sourcepos` (byte+line/col spans), native wikilinks
  (`[[ ]]`), frontmatter delimiter, tables, task lists, strikethrough, footnotes, autolinks,
  math (`$`/`$$`), description lists, header IDs.
- `clap` (derive) — arg parser (we fully control the grammar).
- `serde` + `serde_yaml` — frontmatter field parsing.
A subprocess wrapper was REJECTED: the hard 90% (structural filters) needs the full AST
anyway, so rg-the-binary would only do the trivial final match while adding IPC; using rg's
*crates* gives the same speed with full structural control and no process boundary.

**Span metadata format (user-specified):** Pandoc/Quarto bracketed spans —
`[visible text]{.class key="security, backend"}`. memgrep recognizes these inline and indexes
the `.class` name(s) + the `key="..."` comma list as greppable metadata. A memory line may be
prefixed: `[summary]{.mem key="security, backend"} the fact sentence…`.

### Design constraints (USER, 2026-06-06 — load-bearing)
1. **LENIENT with every markdown flavour.** There are hundreds of MD flavours; memgrep must
   stay compatible by treating anything it does not understand as PLAIN TEXT, and must NEVER
   crash on an unknown syntax variation. Mechanics: CommonMark/comrak already degrades unknown
   constructs to text (no "syntax errors"); ADD per-file isolation (one bad/binary/non-UTF8
   file is skipped with a warning, never aborts the run — like `rg`) and a PLAIN-LINE-GREP
   FALLBACK so memgrep is ALWAYS ≥ `grep` regardless of flavour. All parsing wrapped so a
   panic in one file cannot kill the process.
2. **MINIMIZE the instructions needed to teach it.** The teaching-skill must be tiny. Achieve
   it by REUSING syntaxes Claude already knows from training — do NOT invent new ones. The
   unifying rules (the whole skill in ~4 sentences): (a) every matcher value is a REGEX, same
   as `grep`/`rg`; (b) any flag that has a `grep`/`rg` equivalent keeps that exact name+meaning
   (`-i -w -v -n -l -c -e -A -B -C -g`); (c) numeric/version ranges use PIP/PEP-440 syntax
   (`>=1.2,<3.5`); (d) wildcards are `*`; (e) different flags AND-narrow, comma-lists within a
   flag OR-widen. Be lenient on input too: accept `2`, `2..3`, `>=2,<=3` for ranges. Goal: a
   Claude can use memgrep correctly from `grep` muscle memory + these 5 rules.

### Build approach: tracer-bullet
Get a THIN end-to-end slice compiling + running first (ignore-walk → comrak-parse → regex →
`path:line:col`, with the leniency fallback), prove the whole dep stack + comrak API against
the COMPILER (do not assert the comrak API from memory — verify by building), THEN widen to the
structural flags. Forced verification: not "done" until `cargo test` is green + `cargo clippy`.

## The arg grammar (committed — rg muscle-memory + pip version specifiers + CSS-ish selectors)

Base (ripgrep-compatible, so any Claude's `rg` habit transfers):
```
memgrep [FLAGS] PATTERN [PATH...]      # PATTERN is a regex (regex crate) applied to SURVIVING text
  -i smart/insensitive · -w word · -n line-nums(default on) · -l files-only · -c count
  -A/-B/-C N context · --json structured · --color · -. /--hidden · respects .gitignore via `ignore`
```

### Code blocks (feature 1–2)
- `--no-code` exclude all fenced+inline code · `--code` search ONLY code
- `--code-lang=python,rust` only those fenced langs (implies `--code`) · `--no-code-lang=bash`

### Frontmatter / metadata (feature 3) — composable, repeatable, AND-combined
- `--fm KEY=REGEX` (e.g. `--fm tags=security --fm verified='^2026-06'`) · `--fm-has KEY`

### Headings (feature 4–6)
- `--heading=REGEX` match heading text · `--level=2` or `--level=2..3` (`#`=1)
- `--in=REGEX` scope search to the section whose heading matches, INCLUDING its sub-sections
  · `--in-flat=REGEX` that heading's direct body only (no sub-sections)

### Heading numbering — pip/semver specifiers (feature 7–9)
- `--num=1.2` prefix · `--num='1.2.*'` wildcard · `--num='>=1.2,<3.5'` (comma = AND, pip-style)
  · operators `> >= < <= == !=`, ranges via comma
- `--depth=N` limit numbering depth (e.g. `--num=1.2 --depth=1` hits `1.2.*` but not `1.2.*.*`)

### Inline emphasis (feature 17 example) — regex applied ONLY inside that markup
- `--bold=REGEX` (**strong**) · `--italic=REGEX` (*em*) · `--code-span=REGEX` (`code`)
  · `--strike=REGEX` (~~del~~)

### Span-class metadata (feature 16) — Pandoc/Quarto bracketed spans
- `--class=security,backend` lines whose span `key="…"` contains ANY (OR) · `--class-all=…` ALL (AND)
- `--span-class=note` match by the `.className` itself (e.g. `{.note}`)

### Lists + GFM structures (feature 13–15)
- `--list` / `--no-list` (bulleted/ordered items)
- `--node=table,quote,math,url,image,html,svg,footnote,ref` restrict to those node kinds
  · `--no-node=…` exclude · individual sugar: `--table --quote --math --url --image --html --svg`

### Links / knowledge graph (feature 10)
- `--links` extract/search link nodes
- `--links-to=NOTE` what this note refers to (referred) · `--linked-from=NOTE` referrers (backlinks)

### TOC + autodiscovery recursion (feature 11–12)
- `--toc` search the index/TOC entries + their descriptions
- `--toc-follow=N` search the TOC descriptions of this file AND of linked files, recursion depth N

### Memory-helper subcommands (the "in addition" part)
- `memgrep index [PATH]` (re)generate `memory-index.md` (per-file summary + full TOC + tags +
  backlinks) — the <10ms realtime indexer the KB design calls for.
- `memgrep links --broken|--orphans` link-graph health.
- `memgrep fact [--cat=…] [--comp=…] [--session=ID] [--kind=…] [--since=DATE] [--until=DATE]`
  first-class query over the one-fact-per-line shape (`^<ISO-ts> … :: …`), time-sorted.

All filters AND-compose; the positional PATTERN is the final regex over whatever text survives
the structural filters. Example:
`memgrep security --num='>=1.2,<3.5' --no-code --class=backend memory/`
= "security" in chapters numbered 1.2.0–3.5.0, outside code, on lines span-tagged backend.

## Feature → implementation map (all = walk comrak AST → filter nodes → regex surviving text)
- code in/exclude, by-lang → `NodeValue::CodeBlock{info}` / `Code` filtering.
- headings/level/scope → `NodeValue::Heading{level}`; scope = node range between a heading and the
  next heading of ≤ its level (sub-sections = strictly greater level).
- numbering → parse a leading `N(.N)*` token from heading text; compare with a pip-style
  version-spec evaluator; depth = count of dotted components under the anchor.
- emphasis → `Strong`/`Emph`/`Code`/`Strikethrough` inline nodes → match within their text.
- spans → inline recognizer for `]{.class key="…"}` (Pandoc bracketed_spans), since comrak
  doesn't parse attributes natively; index `.class` + the `key` list.
- lists/tables/quotes/math/etc. → the corresponding `NodeValue` variants (GFM + math ext on).
- links/graph → `Link`/`Image`/wikilink nodes; build a {file → out-links} map, invert for
  backlinks; `--linked-from`/`--links-to` query it; `--toc-follow` BFS the link graph to depth N.
- output `path:line:col` via comrak `sourcepos`.
