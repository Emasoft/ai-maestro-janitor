## The contract (owner directive, 2026-08-02, verbatim scope)

The janitor's repo-map feature must not merely add the map to CLAUDE.md — it must
restructure CLAUDE.md to be VERY SMALL. CLAUDE.md becomes part of the memory system:
existing content moves into PROJECT-scope wikimem pages; CLAUDE.md keeps links plus basic
knowledge. A janitor-managed CLAUDE.md contains ONLY:

- concise description of the project
- github repo url (and urls of all connected projects — plugins, marketplaces, dependencies)
- the basic lint/build/compile/test/publish instructions
- the project map generated by the janitor
- the index of all wikimem pages, ordered by topic, PROJECT-scoped pages only (this
  replaces the moved CLAUDE.md content)

## Why (beyond the directive)

CLAUDE.md is injected into EVERY turn of EVERY session — the janitor's own cost-law page
calls the harness floor the single largest line item on a busy host. This repo's CLAUDE.md
is ~180KB. Moving narrative into wikimem pages makes it RECALLABLE (symptom-indexed, second
hop only when needed) instead of ALWAYS-PAID. The map fence machinery (TRDD-e247a349)
already solved the hard half: fenced janitor-owned regions inside a human-co-owned file,
with anti-corruption splicing. This feature adds a SECOND fenced region (the wikimem index)
and a contract for everything outside the fences.

## Design (Phase A)

- **`scripts/lib/repomap/markers.py`** — parameterized fence surgery: the existing
  functions gain `start=`/`end=` kwargs (default = repo-map fences), so ONE implementation
  serves both fenced regions. No caller changes.
- **`scripts/lib/repomap/claudemd_slim.py`** (new, pure) —
  - `WIKIMEM_FENCE_START/END` — `<+-+-JANITOR-WIKIMEM-INDEX-{START,END}-(do-not-modify)-+-+>`.
  - `scan_pages(memdir)` → per-page `(name, file, description, tier, wikilinks)` from
    frontmatter (reuses `memory_scopes.iter_note_files` semantics; no memgrep dependency —
    the index must build on a host whose memgrep is stale).
  - `render_index(pages)` → the fenced block: overview first, then each HUB as a topic
    heading with the pages it `[[links]]` to, then unclaimed pages under "Other". Entries
    are one line each, description truncated (the index must stay SMALL — it rides every
    turn). Header carries `digest=` (sha over names+lmd) for a cheap freshness probe.
  - `slim_violations(text, root)` → the contract check: index fence present, map fence
    present, narrative outside the fences under a byte cap
    (`CLAUDE_PLUGIN_OPTION_CLAUDEMD_NARRATIVE_MAX_BYTES`, default 8 KiB), repo URL present.
    Advisory list, not an exception — the detector nudges, humans decide.
  - `narrative_preserved(old_text, corpus_texts)` → the preservation oracle for Phase B:
    every load-bearing token line of the REMOVED narrative must appear somewhere in the
    PROJECT wikimem corpus (reuses `memory_edit_verify.load_bearing_tokens`). No content
    leaves CLAUDE.md without this proof — same discipline as the harvest verifier.
- **`scripts/claudemd_slim.py`** (CLI) — `index` (splice/refresh the index fence, with the
  repomap generator's anti-corruption write: lock, lost-update loop, byte-preservation
  outside the fence, atomic replace), `check` (violations + index freshness; exit codes for
  the detector), `verify --old <file>` (preservation proof against the live corpus).
- **skill `janitor-claude-md-slim`** — the editorial procedure (agent work): classify the
  narrative into topical PROJECT wikimem pages, write them via the memgrep write verbs,
  `verify` until green, assemble the slim CLAUDE.md, `index`, commit. The skill does the
  JUDGMENT; the CLI does the mechanics and the proofs.
- **detector** — extend `project-map-drift` (same file, same cadence, same seen-dedupe):
  when CLAUDE.md carries a map fence (janitor-managed) but `check` reports violations or a
  stale index, emit ONE nudge naming the skill. Nudge-only — CLAUDE.md sits in the cached
  prompt prefix; rewriting it mid-session busts the cache (TRDD-e247a349 §5 applies
  unchanged).
