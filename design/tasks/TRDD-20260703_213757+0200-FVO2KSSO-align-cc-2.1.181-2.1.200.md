## Relevance triage (CC change → janitor surface → action)

### CODE audits (delegate to parallel agents; concrete potential bugs)

**A — hook matcher semantics** (`hooks/hooks.json`, all 16 hooks). CC quotes:
- 2.1.195: *"Fixed hook matchers with hyphenated identifiers (e.g. `code-reviewer`,
  `mcp__brave-search`) accidentally substring-matching — they now exact-match. Use
  `mcp__brave-search__.*` to match all tools from a hyphenated MCP server."*
- 2.1.191: *"Fixed hooks with comma-separated matchers (e.g. `"Bash,PowerShell"`) silently
  never firing."*
- ACTION: read every `matcher:` in hooks.json. (1) Any comma-list matcher was DEAD pre-fix
  and now FIRES — confirm each such hook is still correct now that it actually runs. (2) The
  `post-mcp-response-sanitizer` matches MCP responses — verify its matcher is a proper regex
  (`mcp__.*` or `mcp__[^_]+__.*`), NOT a bare `mcp__` that now exact-matches nothing. Also
  2.1.186: *"hook matchers ... exact-match"* interplay. Fix any broken matcher; add a test.

**B — daemon PID-reuse + build-timestamp handover** (`scripts/lib/global_state.py`,
`scripts/daemon.py`). CC quotes (2.1.200):
- *"Fixed background agents never starting again after a crash left a stale `daemon.lock`
  whose PID the OS reused"*
- *"background-agent daemon handover so a reinstalled older build can no longer take over the
  daemon; build recency is now judged by the version's embedded build timestamp"*
- ACTION: audit `daemon_is_alive` / `acquire_singleton_flock` / `daemon_pid` — confirm the
  FLOCK (not a bare `os.kill(pid,0)` pid check) is the authoritative liveness gate, so an
  OS-reused PID can't make a dead daemon look alive. Confirm `daemon_needs_restart` /
  version-handover can't let an OLDER reinstalled cache version seize the daemon from a newer
  one (mirror CC's build-timestamp recency rule if the current gate is version-string only).
  This may already be SAFE (janitor uses flock) — verify, document the invariant, fix only if
  a pid-only path exists.

**C — hooks exit-2 stderr now surfaced** (all 16 hooks). CC quote (2.1.199):
- *"Fixed `SessionStart`, `Setup`, and `SubagentStart` hooks silently hiding stderr when
  exiting with code 2 — the error is now shown in the transcript."*
- ACTION: grep janitor hooks for `sys.exit(2)` / `exit(2)` / `raise SystemExit(2)` and any
  path that writes noisy stderr then exits 2. Under the fix that stderr now LEAKS into the
  user's transcript — ensure janitor hooks fail-open (exit 0) or keep exit-2 stderr terse +
  intentional. `on-session-start*.py` especially.

### DOCS items (do inline; no agent needed)

**D — subagents background-by-default + error-reporting** (arm skill; workflow rule). CC:
2.1.198 *"Subagents now run in the background by default"*; 2.1.199 *"subagents ... returning
their partial work"* + *"reporting API errors ... as successful results"* fixed. ACTION: note
in the arm skill that `run_in_background: true` on the memory-agent spawn is now redundant
(harmless, keep for clarity); revisit the corpus-distillation rule's "rate-limit-as-STRING"
detection (`callWithBackoff`) — CC now reports subagent errors properly, so thrown-error
detection is more reliable (keep the string check as belt-and-braces).

**E — retry/watchdog env** (CLAUDE.md unattended-overnight note + `session_liveness`). CC:
2.1.186 *"`CLAUDE_CODE_MAX_RETRIES` caps at 15; for unattended sessions use
`CLAUDE_CODE_RETRY_WATCHDOG`"*; 2.1.196 stream idle-watchdog default-on (5-min), disable via
`CLAUDE_ENABLE_STREAM_WATCHDOG=0`; 2.1.199 *"`CLAUDE_CODE_RETRY_WATCHDOG` now raises default
retry to 300 and lifts the 15 cap on `CLAUDE_CODE_MAX_RETRIES`"*. ACTION: the janitor's
freeze-detection assumes a stalled turn needs external recovery — now CC's own stream
watchdog aborts+retries after 5 min. Document the interaction in `session_liveness` freeze
assumptions + the unattended-overnight architecture; reference `RETRY_WATCHDOG` as the
sanctioned unattended knob.

**F — native MEMORY.md compact reminder** (memory rule/skill). CC 2.1.186: *"the agent is now
reminded to compact its `MEMORY.md` index when nearing the size limit."* CONFLICT: the janitor
memory system made MEMORY.md a DEPRECATED STUB that must NOT be trimmed (index moved to
memgrep). ACTION: document that CC's native reminder does not apply to the janitor's stubbed
MEMORY.md (the stub is tiny, never grows) so a future session doesn't "compact" it.

**G — default permission mode → Manual** (2.1.200). ACTION: grep janitor docs/skills for any
reference to the `"default"` permission mode; note `manual` is now the CLI default and both
`default`/`manual` are accepted.
