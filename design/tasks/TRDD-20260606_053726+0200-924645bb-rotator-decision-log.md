# TRDD-924645bb — Persistent rotator decision log

## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative) — 2026-06-06

**What & why:** the rotator's daemon `oauth-rotator-tick` fires every 60s and runs
`cmd_tick` → `cmd_auto`, which makes EXACTLY ONE rotation decision per tick and emits it
via `print(...)` to stdout ONLY. The daemon runs the tick as a subprocess whose stdout is
NOT persisted, so the rotator writes **no `rotator.log` at all** for its core decisions
(the only file-writer in rotator.py is the unrelated *bootstrap* subprocess log). This is
the exact reason the overnight failure was undiagnosable ("what the hell happened??" had no
log to answer it — see TRDD-5539cd6e) and why health can only be checked by running a tick
by hand. The user explicitly asked to "keep refining the oauth rotator with concrete logs
to examine and evaluate if it works as supposed to." This adds that durable trail.

**Decisive evidence (this session):** manual `rotator.py tick --only-if-claude-running` →
`auto: live fmuaddib@gmail.com 5h=15% 7d=35% — within limits` (exit 0) — the rotator WORKS
(reads live, queries real /api/oauth/usage, correctly no-ops below the 97% threshold), but
that line vanishes; no rotator.log exists after the tick.

### Plan (surgical — one helper pair + route the decision prints)
1. Add `_log(msg)` — append `"<localtime+offset> <msg>\n"` to `ROOT/"rotator.log"`. Self-trim
   to stay bounded under the 60s cadence (cap ~256 KB → keep last ~128 KB, drop partial first
   line, atomic os.replace). Best-effort: a log-IO OSError must NEVER crash a rotation
   decision (the decision is also on stdout) — report to stderr and continue. This is correct
   separation of an observability side-channel from the critical path, NOT a fallback of the
   core logic.
2. Add `_decide(msg)` = `print(msg); _log(msg)`. Route all of `cmd_auto`'s terminal decision
   prints (within-limits / 429-streak / unreachable / dwell-defer / switched / degraded-switch
   / no-healthy-alternate / locally-expired-no-alternate / no-live-credential) through it, so
   every tick logs its one decision.
3. `cmd_tick`: capture `_keepalive_refresh()`'s return and `_log("keepalive: refreshed …")`
   when non-empty; route the two keychain-write-REFUSED stderr prints (keepalive + capture)
   through `_log` too (failures deserve a durable record) while keeping the stderr print.
4. NEVER log token values — decision lines carry emails + usage %s + fingerprints only
   (already the case for every print being routed). The log lives under CLAUDE_PLUGIN_DATA
   (gitignored, user-only), same trust boundary as state.json/slots.

### Tests (tests/test_oauth_rotator.py)
- `_log` appends a timestamped line; creates ROOT if missing.
- `_log` self-trims when over the cap and the trimmed file starts on a record boundary.
- `_log` never raises on an IO error (simulate unwritable ROOT) — returns, prints to stderr.
- `_decide` both prints (capsys) AND appends to the log.
- a `cmd_auto` "within limits" run writes one decision line to rotator.log containing the
  email + usage (and NO accessToken/refreshToken substring).
