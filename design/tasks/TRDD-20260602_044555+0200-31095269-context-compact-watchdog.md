# TRDD-31095269 — Context-compact watchdog (agent-in-the-loop)

## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative) — 2026-06-02

**Why this exists:** Claude Code 2.1.x (≈Opus-4.8 window) auto-compact is **broken** for
the user — `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70` no longer fires (#36381); sessions run past
70% of the **1M** window, sometimes to **999k**, where `/compact` itself fails ("not enough
context memory left") → forced `/clear` (total loss). User hits this ~weekly, dozens of
concurrent Claude instances. Native auto-compact cannot be trusted → build an external,
agent-in-the-loop watchdog.

**User's chosen design (2026-06-02, verbatim intent):** a janitor `PreToolUse` hook that on
every tool call **tells the agent the current context %**; the **statusline** writes that %
to a JSON in the project `.claude/` subfolder **throttled to ≤ once / 10 s** (disk-friendly);
the janitor ships an **agent-invocable skill `/janitor-compact-context`** that triggers the
compact. **The agent decides** each tool call whether to keep going or invoke the skill.

### Architecture — producer → consumer → trigger → resume
1. **Producer — statusline → throttled JSON.** Writes `{pct, total_input_tokens,
   context_window_size, iterm_session_id, session_id, ts}` to
   `$CLAUDE_PROJECT_DIR/.claude/context-usage.json`, at most once / 10 s.
   - Source of truth (VERIFIED): the live mid-turn % exists **ONLY** in the statusline stdin
     payload — `data.context_window.used_percentage` / `total_input_tokens` /
     `context_window_size` (statusline.py:454-470). Confirmed via the official hooks doc +
     the 2.1.159 binary that **hook input has NO context/token field** (only `session_id,
     transcript_path, cwd, permission_mode, effort, hook_event_name, tool_name, tool_input,
     tool_response`). So only the statusline can produce the signal.
   - **DECISION PENDING (user):** the user earlier said "do not change the statusline script."
     → implement the write as a **thin wrapper on the `statusLine` command** in settings.json
     (statusline.py stays byte-identical; wrapper tees the throttled JSON then `exec`s the real
     script). Confirm before building whether wrapper vs direct edit of statusline.py.
   - `iterm_session_id` = `$ITERM_SESSION_ID` (present in the statusline subprocess env;
     VERIFIED `w0t3p0:…` this machine) → lets the trigger self-target the right pane.
2. **Consumer — janitor `PreToolUse` hook.** On each tool call, reads
   `context-usage.json` and **injects the % into the agent context** so the agent sees e.g.
   "context 72%" before every tool. **VERIFY:** exact PreToolUse output field that injects
   agent-visible text (`hookSpecificOutput.additionalContext` vs `systemMessage`) and whether
   PreToolUse supports it (UserPromptSubmit definitely supports `additionalContext`).
   - Hook is fast/quiet: just read one small JSON + emit one line. Stale-file guard (if ts >
     ~30 s old, say "unknown").
3. **Trigger — `/janitor-compact-context` skill (agent-invocable).** When the agent decides
   it is too high, it invokes the skill, which fires **ESC → short delay → /compact** to its
   own pane via the user's osascript→iTerm mechanism (`$ITERM_SESSION_ID`). ESC interrupts the
   in-flight turn → idle prompt → `/compact` runs (VERIFIED by user: ESC interrupts; you keep
   everything up to the interrupt). **VERIFY:** the ESC keystroke path + the self-interrupt
   timing (the skill's script interrupts the very turn it runs in).
4. **Resume — PostCompact hook + heartbeat `[janitor-resume]` (✅ BUILT).** After the compact
   the REPL is idle (a compaction does not auto-continue; a hook cannot start a turn). The
   PostCompact hook records the resume directive into `resume-after-compact.flag`; the next
   heartbeat — the only thing that fires fresh turns — emits `[janitor-resume] …continue
   TRDD-xxxx…` and the standing posture resumes it. THIS is the leg that makes the unattended
   overnight loop actually close. Directive source: `resume-directive.txt` (agent pointer) →
   newest in-flight TRDD → none. The P3 skill will write `resume-directive.txt` just before it
   triggers the compact, so the trigger and the resume target are recorded together.

### 🔍 Audit (2026-06-02) — full manual trace of every changed file
- **FIXED — AppleScript injection (defense-in-depth).** `compact_trigger.py`
  interpolated `$ITERM_SESSION_ID`'s UUID straight into the `osascript -e` string.
  Env vars are attacker-settable; a crafted value (`x:" then do shell script …`)
  would inject AppleScript. Added a strict `_UUID_RE = ^[0-9A-Fa-f-]{8,64}$` guard
  → malformed id ⇒ `NO_ITERM` (directive still recorded; user asked to /compact).
  +2 regression tests. A SECURITY plugin must not ship its own injection sink.
- **VERIFIED clean:** producer↔consumer paths/keys match (statusline.py:164-190 ↔
  pre-tool-context-usage); output format matches the existing post-edit-safety hook
  (`json.dump`, no trailing newline); flag-before-ts → ts-before-flag ordering is
  race-safe; one-shot consume of resume-directive.txt is correct; every hook error
  path exits 0; `additionalContext` emitted with NO permissionDecision (advisory).
- **NOTED limitations (documented in README, not fixed — would add unverified
  complexity mid-audit):**
  1. Two sessions in the **exact same working dir** share `resume-directive.txt`
     and `resume-after-compact.flag` → cross-session resume bleed. Worktrees are
     already isolated (own `.janitor/`); the per-session context snapshot is
     session-keyed. Fix (if needed): key the flag by `session_id`.
  2. Stale `context-usage.<session>.json` snapshots accumulate (≈150 B each;
     producer-side prune is a follow-up).
