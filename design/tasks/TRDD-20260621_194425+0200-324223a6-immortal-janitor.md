## The vision

The janitor is the guardian that must never need a human to keep the work going.
It must survive — and automatically recover from — every failure class, using
every channel available, with redundant layers so no single failure can break
recovery itself. When something breaks, a script that never dies notices and
fixes it.

## The 4-layer immortality (each layer resurrects the one below)

```
L0  OS init (launchd / systemd)      — keeps the DAEMON alive: respawn on crash,
    "the anchor's anchor"              relaunch on boot/login, survive blackout.
            ▲ resurrects
L1  GLOBAL DAEMON (never dies)       — the supervisor: detect+recover sessions,
    "the immortal anchor"              self-update, self-heal config, re-arm crons,
                                       run the recovery ladder. Singleton flock.
            ▲ resurrects
L2  SESSION HOOKS                    — SessionStart re-arms the cron + records the
    (SessionStart/Stop/PostCompact)    pane; Stop/StopFailure capture rate-limits;
                                       PostCompact writes the resume directive.
            ▲ resurrects
L3  IN-SESSION CRON (heartbeat)      — best-effort 5-min self-trigger. Session-only
    (best-effort, may die)             is acceptable: L2 re-arms it, L1 watches it.
```

Invariant: **a failure at any layer is detected and repaired by the layer above.**
The cron (L3) dying is repaired by the hook (L2) or the daemon (L1); the daemon
(L1) dying is repaired by launchd (L0); L0 is the OS contract (the only thing we
trust to always run). No layer is a single point of failure for recovery.

## The recovery ladder (run by L1 on a stuck session — "1 is not enough")

Escalating, gentlest→nuclear. Each successive failed wake escalates one rung; a
rung that succeeds (the session makes progress) resets the ladder. Every rung is
logged; the whole ladder is bounded by a crash-loop guard (below).

| # | Rung | Action | Channel |
|---|---|---|---|
| 1 | **esc_nudge** | inject `ESC` (dismiss any rate-limit/oauth modal) + a keystroke that fires a fresh turn | terminal-env-aware (iTerm osascript / tmux send-keys / ai-maestro CLI) |
| 2 | **rearm** | type `/janitor-arm` — restore the heartbeat cron | same |
| 3 | **reload** | type `/reload-plugins` — pick up an auto-update's new hooks/skills | same |
| 4 | **update** | ensure latest: trigger plugin update (daemon already self-updates) + nudge | daemon + terminal |
| 5 | **relaunch** | `claude --continue` in the SAME pane (resume from transcript) | terminal exec |
| 6 | **force_restart** | external kill of the stuck claude pid + `claude --continue` in its pane | daemon exec |
| 7 | **resurrect** | launch a BACKGROUND headless claude whose sole job is to kill+relaunch the stuck instance (when even the daemon can't reach the pane) | background claude / ai-maestro |

ai-maestro channel: when the session is a registered ai-maestro agent, the
authoritative inject is the shipped `aimaestro-agent.sh session command <tmux>`
CLI (already wired in `terminal_trigger._try_ai_maestro_send`) — tried before the
raw keystroke path. The daemon picks the channel by the recorded terminal
identity (TRDD-dccb0b8a NPT), never by guessing.

## Terminal-environment detection → correct injection (user-required)

The daemon MUST detect each session's terminal and use the matching channel:
- **iTerm** (`iterm_session_id` recorded) → osascript targeting that session id.
- **tmux** (`tmux_pane` recorded) → `tmux send-keys -t <pane>` (the existing
  `build_tmux_steps`).
- **ai-maestro agent** → the `aimaestro-agent.sh` CLI (cwd→tmux match).
- **unknown** → degrade to L2 (re-arm at next SessionStart) + a loud alert.
A detached daemon cannot read a session's env, so the session records its
identity (the NPT); the daemon reads it. Empirical per-channel validation is
mandatory before a rung is trusted (read-only targeting test first).

## Anticipate-everything: failure → ready recovery matrix

| Failure scenario | Detection | Ready recovery |
|---|---|---|
| Transient server throttle / API error | stale `rate-limited.flag` + silent transcript | ladder rung 1 (ESC+nudge to retry) |
| OAuth quota exhaustion (429) | rotator usage probe | OAuth rotator rotates account (v0.15.0) + rung 1 nudge |
| In-session cron lost / session-only downgrade | no recent `dispatch.log` + heartbeat-armed stale | L2 SessionStart re-arm; L1 rung 2 (`/janitor-arm`) |
| oauth-exhaust / rate-limit MODAL menu blocking | transcript silent + process alive + flag set | rung 1 ESC dismisses the modal |
| claude process CRASHED / OOM-killed | recorded pid dead + pane exists | rung 6 force_restart (`claude --continue`) |
| claude process HUNG (alive, unresponsive) | transcript silent + pid alive + no modal + ladder ≥5 | rung 6/7 kill+relaunch |
| forced `/clear` or `/compact` | PostCompact hook fired | resume directive (existing) + rung 1 if it then stalls |
| installer corrupts `settings.json` hooks | hook-presence/integrity check fails | daemon re-installs the hook block (atomic) + reload |
| env vars corrupted (CLAUDE_PLUGIN_ROOT, PATH) | scripts resolve nothing | daemon uses ABSOLUTE canonical paths (DATA dir) + re-derives |
| daemon itself dies | launchd sees pid gone | L0 launchd respawns it; heartbeat `ensure_daemon_running` as backup |
| blackout / machine reboot | launchd RunAtLoad | L0 relaunches daemon on boot; daemon re-arms everything |
| relocated to another machine / configs missing | bootstrap finds no DATA/config | daemon re-bootstraps from plugin cache; recreates DATA dir + stub |
| marketplace/plugin update breaks the janitor | self-integrity manifest mismatch | pin to last-good cached version + alert; never run a corrupt self |

Each row becomes a concrete, tested handler. The matrix is the contract: no row
may ship without its detection AND its recovery both implemented and tested.

## Crash-loop guard (mandatory safety on the nuclear rungs)

Force-restart / resurrect can become a restart STORM. Guard: per-session, if
rungs ≥5 fire more than K times in a window W, PAUSE the ladder for that session
and emit a loud alert (PushNotification + log) — the ONE place a human is paged,
precisely because auto-recovery is looping. Never an infinite kill/relaunch loop.

## Why layered, not a single fix
A guardian with one recovery mechanism has one way to fail. The 2026-06-20 freeze
was exactly that: one trigger (the in-session cron), one failure (it died), total
loss. Immortality is REDUNDANCY — many independent layers and many recovery
channels, each backstopping the others, so the probability that ALL of them fail
at once approaches zero.
