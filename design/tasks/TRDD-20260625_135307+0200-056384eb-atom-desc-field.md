# TRDD-056384eb — Atom `desc` field: a ≤64-char one-line summary per atom

## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative) — 2026-06-25

### The request (USER, 2026-06-25 — verbatim intent)
Atom memories are usually a paragraph but CAN be large (tables/code/math). That is WHY the
PreCompact handoff lists only the atom **id**, not the content (TRDD-786efe85). But an id
alone forces the agent to `memgrep` the atom to know what it is — wasteful if it is not
relevant now. So add a new atom metadata field **`desc`** (the short name, to save tokens):
an **extremely concise, ≤64-char** summary — "almost a title". Then (a) `memgrep` shows a
one-line summary per atom in search results, so the agent fetches an atom's full body ONLY
when it is the relevant one; and (b) every handoff lists recent memories as **`id — desc`**.

### The grounded design (verified against the real grammar, NOT guessed)
The atom block-property grammar lives in `scripts/memgrep/src/memory.rs`:
- `parse_block_props` (memory.rs:1005) splits the bracket on TOP-LEVEL commas → properties;
  each property splits on its FIRST `:` → (key, value); the value is **`split_whitespace`**'d
  into a `Vec<String>` ARRAY. `keywords` keeps the whole array (the recall surface);
  single-valued keys (`type`/`ocd`/`lmd`/`claude_mem_ref`/`claude_mem_hash`) take the FIRST
  element via `first_val` (memory.rs:1109).
- So a `desc` PHRASE with spaces is mangled by the default rule: `first_val` would keep only
  the first word, and the array form loses "this is one phrase".

**THE GRAMMAR DECISION (the load-bearing one — hook + memgrep MUST agree) — a SLUG (USER, 2026-06-25):**
`desc`'s value is a **snake_case SLUG** — `[a-z0-9_]+`, ≤64 chars, e.g.
`new_handoff_carries_recent_turns_and_memory_ids`. A slug is a **single token** (no space, no
comma, no `:` / `[` / `]`), which means:
- it drops straight into the EXISTING single-valued-key path — `desc = first_val(&p, "desc")`,
  exactly like `type` / `ocd` / `lmd` — with **ZERO change to `parse_block_props`** (the
  whitespace-split yields a 1-element array; `first_val` takes it);
- it sidesteps BOTH grammar hazards a free phrase would hit: the comma-splits-properties hazard
  and the whitespace-splits-into-array hazard. A slug has neither a comma nor a space.
memgrep + the hook defensively truncate to 64 chars. `desc` is a DISPLAY field, NOT a recall
surface — `keywords` stays the thing FTS ranks on. **DISPLAY transform (USER, 2026-06-25):** the
slug is STORED with underscores (the Obsidian-safe single token) but RENDERED with `_`→` ` in
BOTH memgrep results and the handoff, so the reader sees a natural phrase —
`new_handoff_carries_recent_turns` → `new handoff carries recent turns`. The authoring skill
GENERATES the slug from the atom topic.

### Obsidian-metadata safety (VERIFIED — USER concern 2026-06-25)
The atom marker IS the **Obsidian Block-Properties plugin** syntax (`^<id> [key: value, …]` —
wikimem-model.md:221). Adding `desc` does NOT conflict with or break that structure:
1. **No key collision (the two-levels rule).** The model has TWO metadata LEVELS it says to
   "not conflate" (wikimem-model.md:214): PAGE metadata = the YAML frontmatter (which owns
   `description:`), ATOM metadata = the inline block-property bracket. `desc` lives ONLY in the
   atom bracket — a different LEVEL and a different KEY from the page `description:`. Naming it
   `desc` (not `description`) reinforces the separation. `desc` is not a reserved Obsidian /
   Dataview / native-Properties key.
2. **No structural break.** The bracket already holds arbitrary keys (`keywords`, `type`,
   `ocd`, …); `desc` is just one more. A **slug** value is the SAFEST possible value — a bare
   `[a-z0-9_]` token has no space (can't be mis-split into the value array), no comma (can't be
   mis-split into a spurious property), and no `:` / `[` / `]` (can't perturb the plugin's parse
   or Obsidian's markdown rendering, where the bracket renders as literal text). This is exactly
   WHY the slug form was chosen.
3. **Not an Obsidian native Property.** Native Properties are FRONTMATTER keys; `desc` is an
   inline body block-property, so it never appears in Obsidian's Properties panel — no collision
   with the native Properties feature.
Conclusion: `desc`-as-slug is additive, single-token, and level-separated → provably non-breaking.

### Components (each its own phase; ship incrementally)
**Phase 1 — memgrep (Rust; the grammar SSOT) — `scripts/memgrep/src/`:**
- `memory.rs`: add `pub desc: Option<String>` to `Atom`; in `make_atom` set
  `desc: first_val(&p, "desc").map(|s| truncate_chars(s, 64))` — the SAME single-valued path as
  `type`/`ocd`/`lmd`. NO change to `parse_block_props` (a slug is a 1-element value array).
- `index.rs`: add a `desc TEXT` column to the `atoms` table; store it on insert; bump the
  index schema version so `reindex` rebuilds (forward migration — the sidecar is regenerable,
  gitignored, so this is a clean rebuild, no data migration).
- `search.rs` (+ wherever `find`/`recall` render an ATOM hit): append `— <desc>` to the atom
  result line when present, rendering the slug with `replace('_', " ")` (storage stays the slug;
  display is the phrase). Do NOT add `desc` to the FTS index (keywords is the recall surface;
  desc is display-only).
- Rust tests (`tests/cli.rs` + unit): a page with `^id [desc: a_concise_title, keywords: x y]`
  → the atom's `desc` parses to `a_concise_title` (stored) and DISPLAYS as "a concise title"; an
  over-64 desc truncates; a desc-less atom → `None`; `find`/`recall` output shows the one-line desc.

**Phase 2 — the handoff hook — `scripts/hooks/pre-compact-handoff.py`:**
- `_recent_memory_atoms` currently extracts atom ids via `_ATOM_ID_RE` (`^id [`). Extend it to
  also parse the `desc:` SLUG from the SAME bracket (a `desc:\s*([a-z0-9_]+)` match — a single
  token, no comma/space ambiguity to mirror), truncate to 64, and render `^id — <desc>` with the
  slug's `_`→` ` replacement when present (else `^id`, unchanged). Keep the >5-atoms collapse +
  the privacy/exclusion rules.
- Extend the existing tests: a fixture atom with a `desc` renders `id — desc`; without → id.

**Phase 3 — authoring skills:**
- `janitor-memory-atomize` (writes `^id [keywords: …]` markers): also author a `desc:` — a
  snake_case SLUG (`[a-z0-9_]+`, ≤64 chars) summarising the atom, e.g.
  `rotator_drains_busy_account_first`. `verify_atomize` (memory_edit_verify.py) currently
  asserts atomize ONLY added markers + lost nothing — extend it to tolerate/expect the `desc`
  key (and assert the slug charset).
- `janitor-memory-write` / `-update` if/where they author atoms.

**Phase 4 — docs:**
- `skills/janitor-memory-write/references/wikimem-model.md` (the atom block-property spec) —
  document `desc` (snake_case slug key `[a-z0-9_]`, ≤64, display-rendered `_`→space, NOT a recall
  surface) + the Obsidian-safety rationale.
- `~/.claude/rules/markdown-memory-recall.md` — note the atom `desc` (distinct from the PAGE
  `description:` frontmatter; both are "symptom/summary" surfaces but at different granularity).
- The harness `# Memory` directive already has a PAGE-level `description:`; clarify atom `desc`
  is the ATOM-level analogue.

### DERIVED TASKS (consequences)
1. **Index schema migration.** Adding the `desc` column bumps the `.memgrep/index.db` schema →
   ensure `reindex` detects the version change and rebuilds (the sidecar is regenerable +
   gitignored, so no data migration — but a STALE old-schema db must be rebuilt, not crashed
   on). Verify the existing schema-version guard handles the bump.
2. **Backward-compat of existing atoms.** Every existing atom has NO `desc` → `None` everywhere;
   the handoff + memgrep show id-only (today's behaviour). The atomize pass backfills `desc`
   over time. Forward-compatible; no breakage. (No legacy code path — one grammar, desc optional.)
3. **The slug charset + 64-char cap are ENFORCED, not just documented** — memgrep + the hook
   truncate to 64; the atomize skill emits only `[a-z0-9_]` (spaces→`_`, punctuation dropped). A
   hand-authored `desc` that violates the slug (a space / comma) still degrades gracefully — the
   grammar keeps the first token, or drops a comma-tail as a junk property; never a crash — but
   the skill + the docs SPECIFY the slug so authors produce a clean one.
4. **Hook ↔ memgrep grammar parity test.** The hook's Python desc-parse and memgrep's Rust
   desc-parse must agree. Add a shared fixture string used by BOTH test suites so a divergence
   is caught (same `^id [desc: …]` line → same extracted desc).
