## Scope

The conflict + fact-verify executor: an ultracode Workflow that resolves
contradictory/obsolete notes against source + git history behind an adversarial
N≥3-skeptic destructive gate, never deleting without sourced provenance, all
through the TRDD-A transaction core.

## Key mechanisms

- `skills/janitor-memory-conflict/SKILL.md`: consumes librarian conflict pairs; runs
  as an ultracode `Workflow`.
- Workflow shape: constant-capacity pool (cap=clamp(`WIKIMEM_CONFLICT_POOL`,6,15),
  default ~8), progressive ramped spawn (2–4 s jittered), rate-limit-as-RETURNED-
  STRING classification ({verdict|rate_limited|error}; backoff + re-enqueue; never
  counted as a verdict); `pipeline()` default, barrier only at vote aggregation;
  top-K oldest/most-conflicted per run; flat (≤5-level).
- **Destructive-path gate:** demote/delete only after (a) majority vote of N≥3
  independent skeptic agents instructed to DISPROVE, AND (b) an explicit
  git-history verify stage. Repo resolved from `commit:`/`trdd:` provenance —
  **no provenance ⇒ never delete** (demote/skip). Read-ONLY against project repos
  (never commit in); refuse on a dirty working tree. "No git trace" → delete only
  if the repo was definitively reachable + `git log -S`/blame ran; unreachable/
  ambiguous → DEMOTE. Obsolete-but-true → COMPOUNDING `[^N]` whose WHY is SOURCED
  via the chain, never inferred. Same-timestamp conflict → only one true; older →
  possibly a prior code version (check git). Pre-provenance corpus → delete disabled.

## Acceptance

- Obsolete-but-true → demoted with sourced WHY (not deleted / inferred).
- False-with-provenance + confirmed-no-trace → deleted only post-vote.
- No-provenance → never deleted.
- Rate-limited return → re-enqueued.
- Dirty-tree → skipped.
