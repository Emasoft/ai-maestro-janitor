### 2026-07-29 (later) — the relaunch MIRRORS the original argv; nothing is hardcoded

Landed in `d09243d`, shipped in **v0.65.0**. Supersedes §1 above.

**What forced it:** the 0.65.0 publish FAILED at CPV's security gate,
`CRITICAL=1 skillaudit:code_execution CLAUDE_CLI_PERMISSION_BYPASS` on the
`_RELAUNCH_CMD` literal. The scanner was RIGHT — the plugin was shipping a
permission-bypass invocation. Suppressing the rule or obfuscating the string would
have hidden a real capability while keeping it working: strictly worse than the
finding, and forbidden by both CPV's devitalizer contract and the janitor's own
security-agent contract.

**Owner directive:** don't spell claude's flags at all — read the argv the claude
executable was ACTUALLY launched with and replay that.

**The deeper bug the CPV finding exposed** (the important half): the hardcoded line
GUESSED two flags and DROPPED every other one. A real launch line carries `--model`,
`--mcp-config`, `--agent`, `--settings`, the user's own `--add-dir` set — so recovery
silently relaunched a wedged session as a DIFFERENT session.

`fleet_restart.relaunch_command(pid, project_root)`, most-authoritative first:
live argv (`ps -p … -o args=`, rungs 6/7) → the argv RECORDED at session start
(rung 5 — `dead` means the pid is already gone, so nothing else survives to read) →
`claude --continue`. VERIFIED against the live process: reproduces
`claude --add-dir /tmp --continue --dangerously-skip-permissions` verbatim. Any bypass
is now the USER'S, present only because they launched with it; the artifact ships none.

Three guards, each closing a way mirroring could go wrong:

- **`with_resume`** guarantees a resume flag. Most sessions launch as a bare `claude`,
  so a VERBATIM replay opens an EMPTY session in the recovered pane — and because the
  process is running, the scanner reads it HEALTHY while the whole transcript is gone.
  Silent total loss, worse than not recovering. An existing `--resume <id>` is left alone.
- **`argv_is_claude`** matches argv[0]'s BASENAME, never a substring: a line whose flags
  merely mention the word (`--add-dir ~/Code/claude-plugins`) is not a claude launch, and
  a substring test would let a recycled pid or a doctored `terminal-identity.json` turn
  recovery into arbitrary command execution in the user's own pane.
- **the command is DATA** to every `build_*`, exactly as `session` already is — resolving
  it inside a builder would fire `ps` from merely BUILDING a plan, including under
  `--dry-run`. Same purity contract the sandbox guard enforced on the tmux lookup.

`on-session-start.py` now records `argv` beside the pane identity in
`terminal-identity.json`. **This is the load-bearing half** — without it rung 5 has
nothing to mirror. Only the session can capture it, and only there: the hook's parent IS
the claude process (verified — `getppid()` resolves to `claude …`, not a shell wrapper).
It is recorded even when no pane resolved, because rung 7 needs no pane and would
otherwise lose the flags too.

Tripwire: `test_the_plugin_ships_no_permission_bypass_invocation` fails the suite if any
script spells a `claude … --dangerously-skip-permissions` invocation again. It matches
CPV's SHAPE, not any mention of the flag — banning the mention would forbid documenting
WHY this module mirrors, and that WHY is what stops the next author from adding it back.
It caught two files on its first run, one of which was a docstring that would have
re-tripped CPV.

**SUPERSEDED — do NOT carry forward:** `_RELAUNCH_CMD`, `_TEMP_DIRS`, `_temp_dirs()` and

## The rungs (already named in `session_liveness.RECOVERY_LADDER` 5-7)

- **relaunch (5)** — the pid is gone (`dead`) but the pane lives → type
  `claude --continue` into the pane to resume the session in place. No kill.
- **force_restart (6)** — the pid is alive but hard-wedged (`frozen`, gentle ladder
  exhausted) → `os.kill` the stuck pid, then `claude --continue` in the pane.
- **resurrect (7)** — the pane itself is unreachable → spawn a detached background
  `claude` (via `tmux new-session -d`) that kills + relaunches the stuck one. The
  "launch a background claude to kill+restart a stuck one" the user demanded.

## Notes and lessons learned

[^1]: [ocd:2026-07-08 lmd:2026-07-08] `is_killable`'s claude-cmdline check is

  process. Caught when a gate-order test fixture named its decoy script
