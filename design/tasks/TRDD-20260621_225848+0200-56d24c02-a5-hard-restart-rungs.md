**Load-bearing safety (the invariant the whole rung set hangs on):**
- NEVER kill the user's working session. `diagnose_instance` already guarantees a
  transcript-advancing (active) session is `healthy`, never `frozen`/`dead`, so it
  never reaches a hard-restart rung. `is_killable` is the SECOND gate: it refuses unless
  the pid's cmdline is a real `claude`, the instance is NOT `active`, the pid is not
  this process / the daemon, and the diagnosis is a genuinely-stuck one.
- `relaunch` types `claude --continue` (RESUMES the transcript — not total loss).
- DEFAULT-OFF: `CLAUDE_PLUGIN_OPTION_FLEET_HARD_RESTART_ENABLED` defaults false. Until the
  user opts in, every hard-restart rung is dry-run-logged, never executed.
- Bounded: the crash-loop guard (`session_liveness.crash_loop_tripped`) caps hard-restart
  attempts and pages a human instead of a restart storm.

## The rungs (already named in `session_liveness.RECOVERY_LADDER` 5-7)

- **relaunch (5)** — the pid is gone (`dead`) but the pane lives → type
  `claude --continue` into the pane to resume the session in place. No kill.
- **force_restart (6)** — the pid is alive but hard-wedged (`frozen`, gentle ladder
  exhausted) → `os.kill` the stuck pid, then `claude --continue` in the pane.
- **resurrect (7)** — the pane itself is unreachable → spawn a detached background
  `claude` (via `tmux new-session -d`) that kills + relaunches the stuck one. The
  "launch a background claude to kill+restart a stuck one" the user demanded.

## Notes and lessons learned

[^1]: [ocd:2026-07-08 lmd:2026-07-08] `is_killable`'s claude-cmdline check is
  SUBSTRING-based — a command like `python3 not-claude.py` counts as a claude
  process. Caught when a gate-order test fixture named its decoy script
  "not-claude.py" and the rung FIRED instead of REFUSING. Lesson: test fixtures
  for a substring-matched deny-gate must not embed the matched token anywhere,
  and belt-and-suspenders the fixture (pid=0) so a gate regression still cannot
  reach `os.kill`.
