^ATOM-7J81-FF49 [desc: "exit_on_git_root_error gives one stderr line and exit 1 when git worktree list fails, never a fallback root; hooks tell Claude when the board lost its LOCAL cards", keywords: detector_traceback_when_git_worktree_list_fails GitRootError_one_line_exit_1 trdd_common_exit_on_git_root_error _main_checkout_root_lru_cached_no_fallback_root DETECTOR-FAIL_3-strike_streak test_detector_git_root_error_AST_finds_every_caller test_cli_git_root_error_failing_worktree_list_git_path LOCAL-scope_cards_dropped_from_the_board SessionStart_trdd-state_hook_prints_one_line_before_STATE_block PostCompact_resume_hook_stderr_debug_log try_else_so_except_cannot_raise_NameError_after_failed_import findings_cli.py_ticket_cli.py_fleet_status.py_git_failure janitor#342_item_2, type: reference, trdd: TRDD-56FOY1U1, ocd: 2026-11-19, lmd: 2026-11-19]

A failing `git worktree list` inside a known repo used to escape as a multi-line GitRootError traceback on agent-visible stderr (janitor#342 item 2). trdd_common.exit_on_git_root_error (TRDD-56FOY1U1) turns ONLY a GitRootError into one scrubbed stderr line naming the tool and exit code 1; the dispatcher records error:rc=1 and its 3-strike streak raises DETECTOR-FAIL, so the failure stays visible; any other exception still propagates (fail fast). It NEVER returns a fallback root, because _main_checkout_root is lru_cached and a memoised fallback would point a linked worktree at the wrong LOCAL design root for the whole process. Wrapped entry points: five TRDD detectors (trdd-drift.py, trdd-reminder.py, trdd-state-reconciliation.py, trdd-cross-card-blindspot.py, report-to-trdd-drift.py; 20d4a27b), twelve PROJECT-domain detectors that reach trdd_files through issue_catalog raise_issue, clear_issue and reconcile via ticket_proposal (branch-protection.py, agent-context-integrity.py, typosquat-watcher.py, historical-cache-scan.py, mcp-rugpull.py, package-manager-policy.py, ai-context-poisoning.py, workflow-security.py and others; c6c8d4bf, TRDD-7KPG2PCO), and the CLIs findings_cli.py, ticket_cli.py and fleet_status.py (5d39a011). tests/test_detector_git_root_error.py finds every detector that calls the issue functions BY AST and asserts its __main__ block wraps main (three HARNESS-only callers are exempt and the exemption list must stay a subset of the real callers); tests/test_cli_git_root_error.py runs each CLI against a fake git (conftest fixture failing_worktree_list_git_path). Hooks (ad6adb5e): the SessionStart trdd-state hook and the PostCompact resume hook read the board inside one try that also held the import and swallowed every exception, so on a git failure the LOCAL-scope cards vanished from the board and the resume directive silently; each now imports in one guard and reads in another (try/else, so an except naming trdd_common can never raise NameError after a failed import); the SessionStart hook prints one informational line to stdout (it reaches Claude as context) BEFORE any STATE block, the PostCompact hook logs the same cause to stderr (exit 0 stderr goes to the debug log only).


^ATOM-RDMJ-6Y4E [desc: "a failing detector is announced when its failure starts or changes, not every fire; agent-context-integrity honours [[suppress]] waivers but never for a verified exfiltration", keywords: degraded_line_repeated_every_heartbeat_fire _track_detector_streak_announces_only_on_change DETECTOR-FAIL_HIGH_finding_at_pass_3 state_error_hid_a_detector_failure unwritable_state_dir_failure_announced_every_pass janitor#342_degraded_line_autonomous_reader_investigates design-tracked_autofix_git_add_by_name_issue_344 agent-context-integrity_.janitor.toml_suppress_waiver waiver_must_not_silence_verified_exfiltration suppression.load_shared_with_workflow-security rule_id_required_no_blanket_waiver issue_339_waiver detector_failure_looks_like_a_clean_pass_on_stdout, type: reference, trdd: TRDD-TZBTDF56, ocd: 2026-11-19, lmd: 2026-11-19]

Heartbeat degraded line (TRDD-TZBTDF56, janitor#342): a1e0b8a3 printed "degraded:" after [janitor-quiet] on every failing pass, so a persistent failure repeated one unchanged line into the agent's context on each fire and a bare status line invites an autonomous reader to investigate. cd1c5d3b: _track_detector_streak announces a failure only at the START of a failure episode or when the outcome changes, read from the existing streak stamp with no new state, and the line names the non-action. Trade-off: passes 2..N of an unchanged failure look like a clean pass on stdout; the HIGH DETECTOR-FAIL finding at pass 3 and the outcome stamp remain (DELETE was the alternative; the card records why KEEP won). 112cf17e: the outer except (OSError, ValueError) of that function was a bare pass, so when state_dir() raised, or the stamp write raised after an unchanged failure skipped the append, the failure reached no degraded line at all; the except now appends name=outcome for every error outcome (they all start with error:, checked: error:timeout, error:spawn-failed, error:rc=N) with a membership test against a second entry on the same pass; accepted: with an unwritable state dir the stamp never advances, so the failure is announced on every pass. Other detector changes: design-tracked.py (849ae11b, #344) under autofix runs `git add -- <rel>` per untracked design card (by name, never -A, logs and continues per-file failures; the dedupe key includes the autofix state so an autofix-off warning does not suppress the autofix-on line the same day). agent-context-integrity.py (fc339e83, #339) honours .janitor.toml [[suppress]] waivers through the same suppression.load(project_root) table workflow-security.py uses; a waived finding is dropped BEFORE it can print, open a proposal or keep a standing ticket alive, each waiver is logged via state.log_line, rule_id is required (no blanket waivers), paths and sha narrow, and the check sits AFTER the exfil-structural-probe branch so an owner waiver can never silence a VERIFIED exfiltration alarm.

Test and fixture lessons of 2026-11. (1) scripts/lib/privacy_patterns.py (3a5799b0, TRDD-KSUIEPTQ): the pii-us_ssn shape (3-2-4 digits, optional separators) matched digit runs inside hex ids (commit sha a268903483c2, a 32-hex id) and blocked the first commit of the tracked reports/ folder on 2026-11-14, because the guard (?<!\d)/(?!\d) let a run bounded by a-f letters look like a bare 9-digit SSN; the boundary is now "no hex digit on either side" at the main _US_SSN pattern and its three inline copies (log-call, error-response, telemetry); accepted trade-off: an SSN glued to a letter a-f is no longer flagged. (2) 728bf64a (TRDD-KT0G5A43): fixtures holding phrases such as "ignore previous instructions" as plain text raise a prompt-injection alarm or get a tool output stripped whenever an agent reads the file, so each phrase in a string literal is two adjacent literals ("ignore" " previous instructions", runtime value unchanged) and in docstrings it is hyphenated; 11 test files plus one description string at line 334 of scripts/lib/ai_jailbreak_patterns.py (shipped code, no pattern changed). (3) system-daemon-runaway.py (TRDD-NLHVLGEP): in the 3.9.6 publish gate test_cpu_runaway_needs_two_fires_end_to_end failed (CPU measured from a host process that held the synthetic pid 74805); 65fe0cfc made _gather_cpu_times return {} under JANITOR_PS_SNAPSHOT, but b86c4ebe REVERTED it: a snapshot row may carry a REAL pid on purpose (tests/test_runaway_measured_burn.py starts a real busy child and needs the real `ps -p <pid> -o time=` lookup); the defect was the fake CPU row in tests/test_system_daemon_runaway.py, which got a pid no host can hold (dadcf731). Lesson: fix the fixture, not the production seam. (4) terminal_trigger.py inject_until_sent (87ff6f8a, issue #343) logs one line per malformed read-back with the field text, the box width from _box_width and the command length, to test the hypothesis that a long command wraps in a narrow prompt box; the field text can hold the user's own keystrokes (the give-up line already logged it); the call is unguarded like the other log_line calls there and its runtime text is unverified by any test.

Small detector and hook fixes. stale-stash.py (3093b7c0, TRDD-F987RQNV, issue 367): the dedupe key was a crc32 of the positional ref plus commit time and the advisory told the user to run git stash pop and git stash drop on that ref, but stash@{N} shifts when a newer stash is pushed or one is dropped, so the key re-emitted already-nudged stashes and the suggested command could act on another stash; the key is now stash@<commit sha>@w<week>, the advisory names the sha (git stash show -p <sha>, then the current index from git stash list --format=%gd %H, then pop or drop with that index; no bare pop or drop is printed because those act on stash@{0}); the key format changed so each already-nudged stash is reported once more after the upgrade, by design; tests/test_stale_stash.py (2, real git). scripts/hooks/pre-tool-context-usage.py (417297cd, TRDD-BEA87JS1, issue 342 item 5c): the PreToolUse context-usage hook floors token counts to 10k buckets for cache stability, so a distance under 10k rendered as "~0k until the auto-compact point" when it was smallest and most urgent (9f7abe3e had fixed only the budget hook's own renderer; this hook keeps a separate _bucket_tokens); below 10k the bucket is now 1k wide, the label stays byte-stable within a band, and only a count under 1k reads ~0k; rejected: a floor on the distance alone, which would leave every other sub-10k label rendering ~0k (tests/test_pre_tool_context_usage.py, test_context_size_guard.py).
