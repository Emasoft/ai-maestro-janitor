^ATOM-NL5O-D0BR [desc: "The compact pipeline: extract_items, then score_items via the OpenRouter Jev model, then compose (--out full copy, optional --inject-out smaller injected copy).", keywords: what_is_jev_compaction what_does_jev_compact.py_compact_do difference_between_--out_and_--inject-out extract_items_score_items_compose openrouter_jev_model score_once_render_twice does_jev_score_my_own_prose what_is_jevctx how_does_the_compact_CLI_work card_5_two_renderings full_context_path_READ_FIRST_line what_is_LANE_INJECTION_MAX_BYTES, ocd: 2026-09-24, lmd: 2026-09-24]

jev_compact.py's compact subcommand runs a fixed three-stage pipeline: extract_items builds Item objects from the raw transcript JSONL; score_items sends batches to the OpenRouter Jev model (jevctx) and records kept/oversized/decision scores; compose renders the result. Per TRDD-RAEGS1D5 card 5 (score once, render twice): --out ALWAYS gets the full, card-3-sized document, with full_context_path pointing at it; an optional second compose() call, given --inject-out, renders a SECOND, smaller rendering with --max-elided-pointers/--inject-max-bytes applied and a READ FIRST first line naming --out's absolute path, for the SessionStart hook's tight injection budget (~8KB, jev_compaction_lane.LANE_INJECTION_MAX_BYTES for the automatic lane).


^ATOM-YTO8-4QAC [desc: "The post-clear SessionStart hook: per-pane sidecar consume, a synchronous 60s run_compact bound, NEVER RAISES, and on failure spawns a detached summarizer with an llm-ext fallback.", keywords: post-clear_summary_missing why_is_the_compaction_hook_slow run_compact_bound_60_seconds per-pane_sidecar_resume-after-clear does_jev_block_session_start what_happens_if_run_compact_times_out llm-ext_fallback_detached_lane on-session-start-post-clear-compact.py sidecar_consumed_rename why_is_this_hook_synchronous RUN_COMPACT_TIMEOUT_S fact-only_template_fallback, ocd: 2026-09-24, lmd: 2026-09-24]

scripts/hooks/on-session-start-post-clear-compact.py is the SessionStart hook that Jev-compacts a JUST-CLEARED session's OWN transcript and injects the result, synchronously (unlike summarize_previous_session.py's detached hold-and-release). It consumes a PER-PANE sidecar (resume-after-clear.<pane-key>.transcript, written at the verified Enter by clear_trigger._persist_resume_state, keyed via state.pane_key_from_terminal) so two panes of the same project clearing at once never read each other's sidecar; the sidecar is atomically renamed to .consumed-<now> before reading. Its own run_compact attempt is bounded by _RUN_COMPACT_TIMEOUT_S = 60 (seconds), well inside the hook's own hooks.json timeout (90s). NEVER RAISES: every branch degrades to "print nothing, log why" rather than blocking the fresh session's first turn. On failure or timeout (owner decision 2026-09-23 R2) it still injects a fact-only template synchronously, but ALSO spawns a DETACHED summarize_previous_session.py --transcript <this transcript> (same Popen shape as on-session-start.py's own spawn) so the owner's "retry for 5 minutes, then llm-ext" fallback budget -- which the synchronous hook has no time left to spend -- is spent by a process that can afford to.

Now enforced in code: extract_items records the session's LAST compact_boundary, its preserved uuids, and the isCompactSummary entry paired to it by anchorUuid, reset on every boundary. split_conversation keeps live owner/assistant/control messages (after the boundary, or preserved across it) OUT OF SCORING -- score_items and the shadow log see only tool and event items.
