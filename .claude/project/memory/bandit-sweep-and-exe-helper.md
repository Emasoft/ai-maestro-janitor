^ATOM-ULTP-36OV [desc: "exe(name) resolves a bare tool name under the call's PATH to clear B607; pass no env unless it changes PATH, because ubs flags an env-derived executable as command injection", keywords: bandit_B607_partial_executable_path_fix exe_path.py_exe(name_env) exe()_hardens_nothing_same_PATH_search_as_subprocess ubs_command-injection_critical_after_exe(name_env) pass_no_env_to_exe_unless_the_env_sets_PATH capture_all_logins.known_emails_keeps_env test_pre_push_python_floor_local_env_ruling_for_owner_veto git_env_os.environ_plus_GIT_OPTIONAL_LOCKS_taint test_exe_path.py test_git_optional_locks_guard_exe_git_argv_head, type: reference, trdd: TRDD-SWQXCIOS, ocd: 2026-11-19, lmd: 2026-11-19]
scripts/lib/exe_path.py exports exe(name, env=None): it returns shutil.which(name, path=os.pathsep.join(os.get_exec_path(env))) or name. It resolves the program the way subprocess does at exec time, so an env= with its own PATH (a test's fake tool on PATH) still wins, and a missing tool returns the bare name so the call fails exactly as before (FileNotFoundError handling unchanged). It hardens nothing and says so in its docstring (the card records the departure from the canon shutil.which(name)); it only keeps the bare literal out of the call so B607 stops firing. Call it at the use site, never as a module-level constant (that would freeze PATH at import). Batch rule: pass NO env unless the call's env changes PATH. Why (e98d5f0d): ba11166c first converted 16 sites to exe(name, git_env) where git_env was os.environ plus GIT_OPTIONAL_LOCKS, and ubs reported a NEW python.taint.command / py.security.command-injection critical at each git site (doctor.py 0 at HEAD~1, 2 after), because it reads os.environ -> git_env -> executable as user input selecting the program; all 11 such envs were read first and none sets PATH, so exe(name) finds the same program and the env still goes to subprocess.run unchanged. The one exception keeps the env: capture_all_logins.known_emails passes its caller's env parameter, which may set PATH (ubs still flags it; ruled a false positive because the same env reached subprocess.run before). abc77e68 records an agent ruling for owner veto that exe("python3", env) with a LOCALLY built env (test_pre_push_python_floor) widens that exception.
