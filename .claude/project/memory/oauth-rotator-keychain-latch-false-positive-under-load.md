# oauth-rotator-keychain-latch-false-positive-under-load


^ATOM-4H2E-E0DY [desc: "security stalled 13:59-15:08 in two process trees (cause unknown); the latch read 3 timeouts as a denial and blinded rotation 39 min; python latches on ONE timeout; attribute-only reads latch too; fix", keywords: janitor_failed_to_rotate keychain_denied-latch_set security_op_timed_out_past_5s rotator_STUCK_keychain-latched no_live_credential rotation_blind_while_security_stalled half-open_probe_timed_out_re-latched latch_cooldown_600s TIMEOUT_LATCH_THRESHOLD_3 attribute-only_read_never_prompts a_timeout_is_not_a_denial account_hit_5h_cap_unrotated manual_login_forced 97_percent_switch_threshold_too_late burn_gate_ROTATE_HORIZON_MIN rotator.log_empty_while_server_owns_the_tick read_pm2-out_for_server_rotator_beats tmux_server_keychain-blind_keychain_probe_timeout cascade_renew-cookie_latch_artifact, type: project, trdd: TRDD-3VIXO8FA, ocd: 2026-09-05, lmd: 2026-09-05]
**A stalled `security` call is not a keychain denial, and the latch that assumes it is blinds rotation exactly when the keychain is slow.** Measured 2026-09-05: with the ai-maestro server owning `oauth-rotator-tick` (no gap >5 min between decision lines 09:46→14:16), three consecutive slot reads timed out at the 5 s budget and `safe-storage` set `keychain-denied.latch` ("cause NOT observed"). Every beat for 39 min then read "no live credential / STUCK keychain-latched"; the 600 s half-open probe was itself a 5 s `-w` read, timed out and re-latched (one probe recovered, two re-latched); a recovered read took 2851 ms. The live account's last reading was 82%; the owner re-logged in by hand (cap crossing inferred, no 429 recorded). WHY `security` stalled is NOT established: host loadavg 18-27 is an untested correlation; a second process (the server's tmux keychain watchdog, same uid; one securityd session not checked) saw its probe hang eight times in the same window, onset 31 min earlier. Interval slopes were noisy (0.4-3.6 %/min), so the 97% trigger fires 1-7.5 min before the wall. Policy defects: (1) python `safe_storage.run_security` latches on ONE `TimeoutExpired` (safe_storage.py:303-305); the TS port needs 3 consecutive (ai-maestro TRDD-MFTDMSJY); attribute-only reads (no `-w`) route through the same branch (denial MARKERS keep latching). (2) The TS port has no burn-gate projection. Fix TRDD-3VIXO8FA removes the false positive for TRANSIENT stalls only; under a persistent block the latch does what it was built for (stop spawning `security` while calls hang) and rotation stays blind — whether a prompt flood was prevented or reads were needlessly suppressed is the unmeasured cause; that blindness is the alert path's defect. Peer proposal ai-maestro TRDD-RA2ZSTOF wants one shared contract. While the server owns the beat, rotator.log carries only the janitor's rare beats — read pm2-out/pm2-error; a latched beat's `cascade: renew-cookie=…` line is an artifact.
