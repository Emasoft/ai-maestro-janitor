# ubs-partial-scan-pre-commit-gate


^ATOM-WSY2-9LEV [desc: "pre-commit stage 3 blocks when ubs did not run; ubs_partial_gate.py lets one tracked file and detector end partial if no line at or after the anchor changed", keywords: commit_blocked_ubs_exit_2_partial ubs_partial_gate.py_allow_one_partial_scan git-hooks/ubs-partial-allow.tsv_path_detector_anchor_reason ubs_sql_injection_SQLFlowLimit_analysis_incomplete pre-commit_stage_3_ubs_staged_report_json ubs_findings_never_block_scanner_that_did_not_run_blocks ubs_report_must_carry_totals_and_scanners empty_staged_set_report_file_zero_bytes partial_HEAD_blob_same_detector_safeguard anchor_matches_exactly_one_line_of_the_HEAD_blob staged_diff_touches_line_at_or_after_the_anchor_blocks test_precommit_ubs_partial.py rotator.py_cannot_be_committed_ubs_partial, type: reference, trdd: TRDD-H7884ERZ, ocd: 2026-11-19, lmd: 2026-11-19]

git-hooks/pre-commit stage 3 runs `ubs --staged --format=json` (TRDD-Y3B4HPTF, ad33dbde): FINDINGS NEVER BLOCK (ubs reports per rule with samples capped at 3, so no stable per-instance identity exists to diff against; 73 criticals and 300 warnings already existed at HEAD) but a scanner that did not actually RUN blocks: ubs absent, exit 2 without a covering allow entry, an unrecognized exit code, or an unparseable report. c34bd069: a parsed report must carry BOTH `totals` and `scanners` and the counts line must be exactly three fields, because `.get("totals") or {}` had turned a wrong-brace parse or a schema change into "0 0 0" and a false "no critical findings". b72aff2a: an empty staged set is recognised from the report FILE (ubs exits 0 and leaves a 0-byte report, `[ ! -s "$ubs_report" ]`), not from ubs prose. Partial scans (59309705, TRDD-H7884ERZ): since ubs 5.5.26 the sql_injection detector ends partial (exit 2, status "partial", "detector sql_injection: SQLFlowLimit: ... analysis is incomplete") on scripts/oauth_rotator/rotator.py, and the hook blocked every exit 2, so no rotator.py change could be committed. Owner ruling 2026-11-19: a narrow TRACKED exemption. The pre-commit `2)` case runs git-hooks/ubs_partial_gate.py --allow git-hooks/ubs-partial-allow.tsv --report <staged ubs report> (stdlib only, plain python3). The allow file is TAB-separated, 4 fields per line: path, detector, anchor, reason (one entry per path; blank lines and # lines ignored; any malformed line blocks every exit-2 commit). The gate re-scans each staged .py file and its HEAD blob in sibling temp dirs and passes only when ALL hold: the file has an entry, every partial detector equals the entry's detector, the HEAD blob is partial with the same detector (an agent-added safeguard, recorded on the card for owner veto), the anchor text matches exactly ONE line of the HEAD blob, and the staged -U0 diff changes no HEAD line at or after that anchor line. WHY the anchor: it marks the limit site, so the code below it is what the detector did not analyse; editing only above it keeps the unscanned region byte-identical. Every error, missing entry, other detector, HEAD blob not partial, ambiguous or missing anchor, unparseable diff or touched line at or after the anchor makes the gate return 1 (block): no fallback and no skip. decide() holds the pure logic, main() only gathers inputs. tests/test_precommit_ubs_partial.py (33 tests, one real ubs and git end-to-end) pins it.

The only allow entry (scripts/oauth_rotator/rotator.py, sql_injection, anchor refresh_oauth_token(blob, on_failure=failure_cause.append)) existed because ubs 5.5.26 could not follow a BOUND LIST METHOD passed as a callback: failure_cause.append is a "list mutation capability escape" and the detector stopped there (SQLFlowLimit), so everything below was unscanned; every B607 and B110 change to rotator.py (4b2d5784) was therefore made above line 3050 and committed through the entry. 096e22eb then passed `on_failure=lambda cause: failure_cause.append(cause)`, same behaviour, and ubs finished (status ok, failed_modules empty), so the entry was RETIRED and its pinning test became a check that every remaining entry names an existing file whose anchor matches one line (the file now has none; parse_allow still raises on a malformed line); a comment at the call says why it must stay a lambda. The full scan shows the same 4 findings as the partial HEAD scan with shifted lines (hardcoded-secrets, ctcompare.secret_eq, popen_handle, taint.command); later, 68fadd84 renamed REFRESH_FAIL_CREDENTIAL_DEAD to REFRESH_FAIL_REVOKED_GRANT (value unchanged; ubs flagged hardcoded-secrets and ctcompare.secret_eq only because the NAME contains CREDENTIAL, cleared in a scratch-copy test and a re-scan), leaving only the taint critical and the popen_handle warning at line 3312; TRDD-Z691NW1P (triage) and TRDD-FSNVU81M (tests for the helper, fe16ed55) were closed on 2026-11-19. Other ubs facts from the same days: ubs 5.4.17 did not finish its js module on hooks/secret-shield pipeline.ts and pipeline.test.ts scanned together (900 s in the hook, then 300 s three times, while each file alone took about 3 s), so the two were committed in separate commits; passing an env derived from os.environ to exe() makes ubs report a command-injection critical (see bandit-sweep-and-exe-helper); a ubs sparse-array warning at shield_scan/jsonl.ts:45 was judged a false positive (spread of a typed array). Test fixtures shaped like secrets (a 64-char base62 literal) trip ubs too, so they are generated at run time.
