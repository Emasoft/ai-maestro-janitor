# secret-shield-core-passes-and-redaction-bridge


^ATOM-X0PK-VPLN [desc: "home.ts redactHome rewrites home prefixes to ~ or %USERPROFILE% as a pure core export that the live mod does not call; JSON-escaped Windows homes at any depth are covered", keywords: home_path_left_visible_in_sanitized_text redactHome_home.ts home_prefix_rewritten_to_tilde_or_USERPROFILE Windows_home_JSON-escaped_twice_stays_visible long-path_prefix_JSON_escaped_drive home.test.ts_known_misses home_after_}_or_)_rewritten Unix_home_with_@_domain_realmd second_run_counts_hits_again_USER_slug lookbehind_backslash_run_quadratic_bun report-sanitizer_routes_home_paths_through_redactHome live_mod_does_not_rewrite_homes_tools_need_absolute_paths, type: reference, trdd: TRDD-L1I0FP5T, ocd: 2026-11-19, lmd: 2026-11-19]


hooks/secret-shield/home.ts exports redactHome(text, homes), the shared home-prefix rewrite (49a9d171, TRDD-L1I0FP5T). Owner order 2026-11-16: never mask a path except the home prefix, which becomes ~/ on Unix and %USERPROFILE% on Windows; the same function serves the report sanitizer and the shield so they cannot drift. It is pure (the caller passes the home literals it knows) and separate from redact(): a home path is not a secret, so redact() and its hits are unchanged, and the live mod does not call it (whether tool results get it is an open owner decision, because tools need absolute paths). A drive letter counts only at a token start, so PATH lists (/opt/bin:/Users/<name>) and file: URLs keep their text and only the home part becomes ~; Public, Default, All Users and Shared are not people. Later fixes: SEP is a backslash run of ANY length or a slash and the Users folder matches in any letter case, Windows names may hold @ and $ (4516b88d); Unix names may hold @ (realmd /home/%U@%D); the slug rules skip a name that is exactly USER so a second run counts 0 hits; a Windows home JSON-escaped at any depth is a home, because each JSON level doubles every backslash (2b72f4f6), and the long-path prefix is one lookbehind (two or more backslashes, a question mark, one or more backslashes) guarded by a lookahead for a letter and a colon: unguarded it is about quadratic in bun 1.3.14 (20,000 backslashes took 8.9 s, 43 ms guarded); a long-path drive in JSON text is a home again (5edc66b3); a home after } or ) is rewritten again (09d5d5e6: HOME_START refused a slash right after } or ), privacy order wins over a possible false hit, ~ still refuses because a second run must not match ~/Users/x). Known misses pinned by tests in hooks/secret-shield/tests/home.test.ts: relative ../Users/<name>, a name after ${VAR} or $(cmd) in some shapes, URL-encoded slashes, a Windows name with round brackets or & ! # % ~ { } ^, a Linux name ending in $, a drive letter glued to a name character, a spaced Windows name with no separator after it. The claude plugin test runner does not slow down without the lookahead guard, so home.test.ts cannot pin it; a bun-run timing test belongs in report-sanitizer, which runs this core in bun.


^ATOM-B2VV-LJ9D [desc: "pipeline.ts redactAll owns the pass order secrets, cards, email, home and throws on an unknown or empty pass set; email cloneAddresses defaults to visible", keywords: which_order_do_the_shield_passes_run redactAll_pipeline.ts secrets_cards_email_home_pass_order empty_pass_set_throws bridge_op_all_passes_array email_cloneAddresses_visible_hidden_rule_G git_clone_address_visible_in_email_pass bearerBare_crosses_line_break Bearer_rule_masked_a_path_on_the_next_line pipeline.test.ts_cards.test.ts_email.test.ts ubs_scan_did_not_finish_two_files_together home_pass_half_the_CPU_leave_it_out, type: reference, trdd: TRDD-L1I0FP5T, ocd: 2026-11-19, lmd: 2026-11-19]


hooks/secret-shield/pipeline.ts exports redactAll(text, homes, passes), the one core entry point that owns the pass order (064caad4, increment 5 of TRDD-L1I0FP5T): secrets, cards, email, home, in that fixed order over a chosen set of passes, merging the hit counts. Before it the order lived in each caller (the janitor bridge ran redact then redactHome; report-sanitizer ran redact, redactCards, its Python rules ending in email, then home) and the scan skill would have been a third copy. Why this order: cards run after secrets, so a digit run inside a token is already a marker and the card pass cannot split a token; email runs before home, so a name inside an email address is hidden by the email pass first. Why a pass SET: the home pass is about half the CPU (TRDD-BAQB9SYO increment 0), so a caller that does not need it leaves it out. Fail fast: a value that is not a pass throws fixed text (no input echoed) and an empty pass set throws because it would return the text unredacted. The bridge gets op "all" with an optional non-empty passes array. The email pass takes EmailOptions { cloneAddresses: visible | hidden } (dcafa805): default visible keeps rule G (a git clone address over SSH is a service account, not a person); report-sanitizer needed hidden to hide nothing less than its Python EMAIL rule; redactAll passes a per-pass options record to the email runner only, and parity was 0 span differences over 60,000 generated lines in hidden mode (1172 in the default mode, so the comparison can see one). The bare Bearer rule stops at a line break (9c9a2b30): bearerBare took \s+ between Bearer and the value, which crosses line breaks, so a path or a variable name at the start of the next line was masked and then hidden everywhere else in the file; it now takes [ \t]+ (43 newline-crossing matches in the code tree, 0 in the plugin cache, all identifiers after a blank line). Tests: hooks/secret-shield/tests/pipeline.test.ts, cards.test.ts, email.test.ts. pipeline.test.ts landed one commit after pipeline.ts because the pre-commit ubs scan (5.4.17) did not finish its js module on the two files scanned together (900 s, then 300 s three times, at high load) while each alone took about 3 s.


^ATOM-3UJM-A7B6 [desc: "redactJsonLine and redactText decode JSON strings so secrets behind escapes are hidden; redactText runs the old plain walks first, then JSON walks, because JSON-first hid less", keywords: secret_behind_JSON_escape_not_hidden redactJsonLine_patterns.ts redactText_redactDeep_redactBlocks_json_walk backslash-n_backslash-u_escaped_secret_visible JSON_document_inside_a_string_secret json-line.test.ts_json-text.test.ts mapJsonLineStrings_one_walker bridge_op_both_returned_16_lines_unchanged JSON-first_order_hid_part_of_a_secret_in_10455_texts 4_MB_JSONL_Read_3_times_slower_hook_limit_10_s redactMemberValue_key_undefined mid-line_secret_name_assignment_known_defect_0UVFDPQP, type: reference, trdd: TRDD-CAZIKQVH, ocd: 2026-11-19, lmd: 2026-11-19]


A secret behind a JSON escape (an escaped newline, tab, quote, slash, a backslash-u sequence, or a JSON document carried inside a string) was left whole because the rules are written for DECODED text: 45 of 124 escaped-form cases in the escape-coverage measurement. Two entry points in hooks/secret-shield/patterns.ts. redactJsonLine (a0f6a29e, TRDD-BAQB9SYO) decodes every string token of a valid JSON line, runs the rules on the decoded text (a member value together with its key, so key-context rules still fire), runs the raw line once, then hides every copy of a found value in every decoded string; only changed tokens are re-encoded; a line that is not JSON goes through redact(); if the result no longer parses it throws a fixed message with no input text so the caller fails closed. Order measured on 134 cases: walk first left 8 whole and none partly; raw line first left 8 whole, 3 partly and broke the JSON of 3 (npmrc before an escaped quote). redactMemberValue takes the one value of the hidden pair, not member[key], because a rule can rewrite the key itself and the lookup by the original key wrote the text "undefined". mapJsonLineStrings (170593c6) is the one walker (hideKnownTokens folded into mapJsonStrings), also used by the home pass of bridge op jsonl; every rewritten token is written back with JSON.stringify. redactText (aac5be3c, TRDD-CAZIKQVH) is what redactDeep, redactBlocks, the bridge op both and the /janitor-secret-shield test dry run use: the old two plain walks run first byte for byte as in bd6bca6f, then walk 3 runs redactTokens on each line that still parses as a JSON object or array, and walk 4 hides every found value where it is copied elsewhere, also behind an escape; over 256 forms go through a prepared index. Why not redactJsonLine per line first: running the JSON walk first showed part of a secret that bd6bca6f hid in 10,455 of 200,000 generated texts; after the old walks it shows more than bd6bca6f in 0 of 200,000; price: in 1,732 texts the JSON-first order hid a secret that this order leaves visible in part (a union of both orders was the next step, TRDD-8O9A2QRS). Accepted risk: a 4 MB JSONL Read takes about 3 times longer (532 to 1659 ms at load 10) against a 10 s hook limit, and a hook that times out after next() leaves the raw result. Mid-line secret-name assignments stay visible as a pinned known defect (TRDD-0UVFDPQP; tests/json-line.test.ts, tests/json-text.test.ts, 15 mutations each turn at least one red).


^ATOM-HE4H-T5KX [desc: "transcripts sent to llm-ext or Jev go through redact_bridge.ts under bun with fail-closed transcript_redact.py; the copy is op jsonl and its sidecar records the op", keywords: transcript_sent_to_remote_model_unredacted redact_bridge.ts_ops_redact_home_both_all_jsonl transcript_redact.py_RedactionUnavailable_fail_closed redacted_transcript_copy_sidecar_op llm_ext_compact.py_requires_--state-dir redacted-transcripts_per-run_folder_24_h_sweep llm-ext_checkpoint_refuses_stale_transcript_prefix Jev_lane_redacts_item_texts_and_digest JevValidationError_invalid_non-retryable _REDACT_TIMEOUT_S_45 217_MB_transcript_took_173_s_redaction compose_agent_handoff.py_llm-ext_lane bridge_not_found_hook_child_PATH, type: reference, trdd: TRDD-TKQ274RE, ocd: 2026-11-19, lmd: 2026-11-19]


Transcripts and prompts sent to outside models go through the shield core, never a second copy (TRDD-TKQ274RE: the summarizer lanes sent session transcripts to remote models unredacted). hooks/secret-shield/redact_bridge.ts runs the core under bun, one JSON request per line, ops redact, home, both, all (a passes array, see pipeline.ts) and jsonl (redactJsonLine then the home pass on each decoded string; a line that is not JSON gets the same output as both; 0f370a4e measured that op both made 3 of 232,754 real transcript lines invalid JSON), with fixed-text errors and exit 2, never echoing input. scripts/lib/transcript_redact.py (stdlib only, so the jev boundary holds) resolves bun (PATH, then the usual install dirs, since a hook child lacks the interactive PATH), redacts texts (redact_texts, op both) or streams a JSONL transcript into a 0600 copy (redacted_transcript_copy, op jsonl via _COPY_OP, 8b5fe69f), and raises RedactionUnavailable on every failure (missing bun, timeout, nonzero exit, error line, count mismatch, broken JSON, invalid UTF-8, unwritable destination): no fallback sends anything unredacted. A copy is reused only while source size and mtime, the homes, the shield files and the OP recorded in the sidecar are unchanged (one _copy_meta serves the reuse check and the write), so a new rule or an older op forces a fresh redaction; an assert on the bridge pipes became an explicit raise (python -O, bandit B101). Callers: scripts/lib/llm_ext_summary.py and scripts/llm_ext_compact.py (the SessionStart fallback) and scripts/compose_agent_handoff.py (the manual handoff) make a per-run folder under <project>/.janitor/state/redacted-transcripts/, write the redacted copy there plus an explicit --checkpoint beside it, pass only that to llm-ext, and remove the folder when the run ends (3a744777): a per-run folder and a digest-named checkpoint because llm-ext refuses forever once a resumed checkpoint no longer matches its transcript prefix; leftovers of killed runs go by a 24 h age sweep. Any redaction failure is a PERMANENT result and llm-ext never runs; a failed REMOVAL only logs a fixed line (the leftover holds redacted text). llm_ext_compact.py requires --state-dir. The Jev lane (scripts/lib/jev_compaction.py, efb3fc38) redacts every scored item text plus the digest with ONE redact_texts call before mkdtemp and argv, a failure raises JevValidationError (stamp kind invalid, non-retryable) so the lane goes straight to llm_ext_compact.py; _REDACT_TIMEOUT_S = 45 (scored set at most 196 KB, 0.1 to 0.3 s on four real transcripts). One real 217 MB transcript took 173 s on a loaded host with a 49 MB Python peak, so callers size timeouts by file size. bun working folder rule: see secret-shield-scan-skill (bun --cwd plugin).
